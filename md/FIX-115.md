# FIX-115 — Catching Market blocked-BUY attribution

## Scope
Read-only Catching Market diagnostics/UI enhancement. **Replay = Production remains the golden rule.** This fix does not change Production or Replay trading behavior.

## Changes
- Preserves exactly one grid row per existing Catching Market aggregate; blocked opportunities do not multiply rows.
- Adds **Blocked BUYs**: count of persisted `execution_opportunity` rows for the same symbol inside the aggregate's exact Start/End window where `direction='BUY'` and `status IN ('BLOCKED','CANCELLED')`.
- Adds **Blocked Why**: distribution of the persisted `decision_code`, ordered by count, e.g. `6 × ORDER_BOOK · 3 × BTC_CONTEXT`. No inferred/fabricated blocker labels are introduced.
- Combines Start and End into one **Start / End KSA** column to save horizontal space.
- Same-day values render compactly as `14:05 - 14:47`; cross-day ranges retain date context.
- Existing 20-row server pagination, history filters and newest-first ordering are unchanged.
- Existing **View chart** remains one action per aggregate and highlights **Start only**.

## Isolation / safety
The enrichment is read-only and queries already-persisted `execution_opportunity` evidence. It does not call or alter signal generation, FinalDecision, ExecutionIntelligence, Order Book evaluation, wallet execution, schedulers, Catching Market detection, or Replay logic.
