# FIX-134 — shared wallet asset writers

Status: implemented candidate alongside the FIX-125 coordination infrastructure. Number reserved after checking the supplied registry (highest previously assigned FIX-132). Confirm this reservation in any external registry before merging parallel work.

WalletService.execute/setAsset and automatic BUY/SELL can both read-modify-save the traded coin quantity and average cost. The old Java monitor did not coordinate the manual service and did not last through commit. This is a demonstrated source-level exposure, not proof that a historical live balance was lost.

All these writers now join the durable symbol/mutation contract in FIX-125. addCashFlow and updateSettings join the mutation guard too, so cash replacement, settings and absent-row initialization cannot bypass automatic mutation serialization. Coin and cash entity reads refresh under a current database lock. Atomic USDT debit/credit statements remain unchanged. Tests verify manual and automatic BUY preserve both quantities, cost and debits.

No scoring/sizing change. Manual trades retain their existing managed-position semantics: this fix does not invent a reconciliation between a manually edited wallet quantity and an automatic position lifecycle. No external/exchange exactly-once guarantee is claimed. Database tools or other applications that write these wallet tables must join the same contract or remain excluded from concurrent operation.
