# FIX-129 — Ingestion and eight-hour block timing diagnostics

Status: candidate implementation; Maven/JUnit and live measurement pending. Baseline: FIX-128.

## Evidence and scope

The September 10 trader logs show the 07:59 UTC one-minute candles reaching close-event workers progressively between 10:00 and 10:15:54 +02:00. Scheduled recovery could read some exact closed candles before the WebSocket processing-completion message. This supports investigating the path after input persistence. It does not prove a particular method blocked.

PriceMoveMonitorService synchronously finalizes its prior eight-hour UTC block before candle-event publication. Its 00:00/08:00/16:00 UTC boundaries align with the observed 02:00/10:00 +02:00 disruption starts. This is a candidate explanation, not a measured root cause. The shutdown stack includes sendCloseMessage; it does not prove a heartbeat failure caused the stall. The excerpt did not establish CallerRunsPolicy activation.

This patch measures existing work. It does not move block finalization, change queries, shorten transactions, alter retries, change executor behavior for analysis, repair candles, reconnect differently, or change Production/Replay business decisions. It does not resolve the deadlock or FIX-125 wallet commit-coordination issue.

## Measurements

KlineTransactionCoordinator wraps its existing transaction calls:

- INPUT_TRANSACTION: upsert and canonical market observation, including commit/rollback.
- PROTECTION_TRANSACTION: each existing attempt separately, including commit/rollback. Correlation ID is shared across attempts; retry policy is unchanged.
- OBSERVER_TRANSACTION: existing observer transaction, including commit/rollback.
- CLOSE_DISPATCH_TRANSACTION: publication transaction and synchronous after-commit handoff. It is not total asynchronous analysis duration; caller-run work, if it occurs, is included.

PriceMoveMonitorService wraps only finalizeBlock with BLOCK_FINALIZATION, inside the existing synchronized tracker block. Reset and subsequent price processing keep their original ordering. All finalizations emit BLOCK_BEGIN and a completion measurement, including short ones. A BEGIN without completion may indicate an unfinished call or interrupted logging/process; it is not proof of its cause.

Elapsed milliseconds use System.nanoTime. started_at/finished_at are actual UTC observation timestamps. Kline context preserves exact symbol, interval, candle_open_time and Binance observed_at; no nearest candle or generated_at fallback is introduced. Block measurements use the prior block_start and deliberately leave candle identity null. Their observed_at is the existing observer's wall-time argument, not Binance event time. Block measurements have separate correlation IDs; match their enclosing observer by symbol and time overlap, not an assumed shared ID.

Slow stages (at least 1,000 ms), failed stages and every block finalization are logged and submitted for persistence. Successful sub-second ordinary stages are omitted. RETURNED means the measured Runnable returned; it does not establish a trade, parity, or final analysis result. FAILED measurements preserve the original thrown exception. Block duration is nested inside observer duration: never sum these as independent work.

## Persistence and review

V87 creates reporting-only fix129_stage_timing, with no foreign key to trading rows. No existing entity/schema is changed. Fields: correlation_id, symbol, nullable interval_code/candle_open_time/observed_at/block_start, stage, started_at, finished_at, elapsed_ms, outcome and thread_name. Indexes support symbol/time review and correlation lookup.

A single dedicated daemon writer with queue capacity 256 performs inserts. JDBC query timeout is two seconds. It never uses CallerRunsPolicy; rejected submissions do not execute JDBC on ingestion threads. Connection acquisition still follows the existing DataSource timeout, so a stalled database can occupy this one writer and fill its queue. Queue rejection, database errors and shutdown loss are best-effort observability limitations. Stage logs remain the fallback. No full exception payload is persisted. Existing logging and diagnostic allocations still incur overhead; zero overhead is not claimed.

Logs: [FIX-129][BLOCK_BEGIN], [STAGE_TIMING], [PERSIST_DROPPED], [PERSIST_FAILED], [DIAGNOSTIC_FAILED].

Proven / Analyze Trades displays Ingestion timing for a saved trade, a run, or an archive, through the corresponding /fix129 read endpoint. It selects the symbol and wall-time measurements overlapping the saved review window, returning at most 500 rows with truncation disclosed. Block identity is displayed separately from candle identity. These are current persisted Production observations, not a frozen archive or simulated Replay result. Historical windows before installation have no measurements. Empty results cannot prove healthy ingestion. No automatic retention deletion is introduced.

## Operator steps

On Java 21 with Maven, from the project root:

```bat
mvn test
```

After successful validation and deployment, Flyway applies V87. Capture the next block rollover; boundaries in +02:00 logs are 02:00, 10:00 and 18:00. In a +03:00 display they are 03:00, 11:00 and 19:00. These are inspection windows, not claims that every rollover will stall.

From Windows CMD:

```bat
powershell -Command "Select-String -Path 'C:\apps\crypto-ai\crypto-ai.log' -Pattern '\[FIX-129\]' | Out-File -Encoding utf8 -Width 4096 'C:\apps\crypto-ai\trader-fix129-timing.txt'"
notepad "C:\apps\crypto-ai\trader-fix129-timing.txt"
```

Compare measured BLOCK_FINALIZATION duration with its enclosing OBSERVER_TRANSACTION. If observer time is high but finalization is short, investigate the remaining observer work/transaction rather than blaming rollover. If protection/input/dispatch dominates, follow that measured stage. No optimization should be inferred from an empty result.

Rollback of application instrumentation can restore FIX-128 while retaining the additive reporting table. Do not modify an already-applied Flyway migration or delete diagnostic history as part of rollback.
