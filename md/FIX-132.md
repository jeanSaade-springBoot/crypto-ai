# FIX-132 — collector sole-source candidate

Status: implemented candidate, OFF by default. No server deployment, database migration or table rename was performed. This Trader-only review delivery uses `pom(20260926-180106).zip` as its baseline. The collector is already deployed separately and is not included here. It is not a measured zero-latency or Production/Replay parity claim.

## Implemented behavior

The source collector must already publish the FIX-132 immutable sequenced feed. Its connection ownership and publisher lease remain collector responsibilities; this package does not replace that deployed application. Existing consumers' claim fields are never updated by Trader. Additional SELECT load still requires measured acceptance.

Trader uses an independent SELECT-only connection to crypto_ai_v2, with its own local delivery state in crypto_ai. OFF retains existing readers and ingestion. OBSERVE reads the immutable feed for diagnostics while retaining old candle readers and ingestion, and applies no feed business effects. LIVE routes repository and direct candle reads to the collector, disables Trader candle import/bootstrap/kline processing and WS startup/reload, and consumes collector prices and closes. There is no local candle fallback. Unrelated APIs such as pair validation and order-book data are outside this migration.

Input evidence, protection, observer and analysis registration have separate local transactions. Source reads finish before local transactions begin; no XA is introduced. Discovery copies source payload and advances its checkpoint atomically locally, recovering by source sequence after rollback. Each effect phase holds its local symbol/event fence through commit. This is not exactly-once wallet execution across every existing transaction boundary.

A durable protection START prevents automatic replay of a crashed or unconfirmed wallet attempt. Only the existing InitialPositionLockDeadlock pre-effect retry remains. Unknown protection results require review and stop the symbol. Observer failure is persisted without repeatedly running it or stopping later price protection. Started analysis is never automatically reassigned; a five-minute threshold marks REVIEW_REQUIRED while allowing the original owner to report completion. FIX-125 now supplies the separate transaction-lifetime wallet coordination in this integrated candidate; see FIX-125.md for the exact mechanism and test limits.

## Approved data and eligibility contracts

Use current committed candles by exact symbol + interval + candle_open_time. Ordered OHLCV fingerprints record analysis and simulation inputs. They detect changed data; they do not archive reconstructible historical versions. Repairs can change subsequent Replay results.

Live protection requires LIVE_WEBSOCKET/LIVE classification, a positive 1m price, original observation time after cutover and not in the future, age at most 15 seconds, and no regression from the last accepted observation. A committed sequence alone never makes an event live. Closed-candle live eligibility is rechecked after indicator calculation: 1m 90s, 5m 120s, 1h 300s, 4h 600s, 1d 1800s, other intervals 120s. Older closes use historical analysis without live execution. These are explicitly approved eligibility changes, not merely data-access changes.

Replay never claims live feed work. OLD/NEW candle readers use shared current history in LIVE mode; price evidence uses LEGACY or APPLIED outcomes in historical order. Pending collector evidence or missing collector-era prices produce an explicit error rather than silently substituting signal prices. Pre-collector fallback remains. verifyEventResolution() and Shadow-write behavior are retained. Real-window parity remains an activation gate.

## Bounds and visibility

Shared pool: maximum 3 connections. Price workers: 2, no more than 2 submitted tasks, round-robin symbols and 8-event task quantum. Discovery: batches up to 100, maximum 200 unfinished price-delivery rows per symbol. Analysis: at most 16 locally submitted tasks, existing executor, ordered per symbol/interval. Independent discovery/price/analysis clocks prevent a slow source read or analysis submission from monopolizing price dispatch. These are initial resource limits, not validated throughput promises; retained database backlog and cross-instance capacity must be measured.

FIX-tagged lifecycle, lag, source-unavailable, sequence-gap and review logs are searchable. Proven / Analyze Trades includes a persisted delivery diagnostic panel. `/api/administration/shared-market` exposes status, bounded event windows and input fingerprints. Empty results do not establish complete coverage. Collector timer `fix132.collector.transaction` spans publisher-containing method entry through transaction completion, excluding pool acquisition/proxy begin. Feed received_at is publisher-entry time, not exact socket receipt; source created_at precedes commit. UI latency from source_created_at is not an exact post-commit transport measurement.

## September 26 review refinements

- V90 adds persisted eligibility_reason without editing the candidate V89 checksum. Historical/noncanonical/stale/future/regressed observations have explicit reasons; observer outcomes and failure details appear in Proven. Row-to-phase timings are explicitly not exact source commit latency.
- Discovery batches commit local payloads and checkpoint together. A duplicate/malformed insert fails the batch rather than being ignored. Discovery and analysis claims respect symbol quarantine; an already-queued task rechecks READY before calling analysis. This does not make wallet entry atomic with future quarantine transitions.
- LIVE recovery authority belongs to shared delivery. Scheduled recovery defers post-cutover or already-delivered candles; pre-cutover untracked backfill cannot execute. Legacy registered-signal recovery retains quarantine but does not automatically retry in LIVE. This deliberately prevents uncertain shared work being executed through a second recovery path. Reconciliation remains manual; missed analysis can remain visible until resolved. OFF keeps existing recovery behavior.
- The source read pool has 2s connection and 5s socket driver limits (individual waits, not an end-to-end deadline). Pool size remains three. Failed local analysis claims release their in-memory lane reservation.
- Local application credentials/configuration from the uploaded baseline are preserved. The review package defaults to OFF, activation-approved=false, scheduled-analysis-enabled=false. No server settings or database tables were changed by creating this package.

## Integrated approval and processing correction

V91 leaves V89/V90 checksums intact, changes new-state default to PENDING_CUTOVER, and demotes existing READY rows without inferring their approval history. Existing review/quarantine states stay intact. OBSERVE explicitly seeds AUTO_OBSERVED/PENDING_CUTOVER and continues discovery/OBSERVED progress in that state. LIVE requires READY + OPERATOR_APPROVED, nonblank approver/reference, approval time, matching approved sequence/time and a corresponding immutable approval-audit row at startup. Runtime admission rechecks the operational approval fields. These are audit provenance fields, not cryptographic proof of a human; database write privileges remain authoritative.

Signal processing carries nullable source_event_id written with registration in the analysis transaction. The delivery must match exact closed-candle lineage; existing work ownership cannot be reassigned. Shared signals use an explicit PaperTradingService route, and legacy/explicit routes cannot claim shared-owned work. First-cutover and restart validation block unfinished unattributed work. Linked unfinished work must have a matching delivery with RUNNING/REVIEW_REQUIRED analysis disposition; orphan/inconsistent links block startup. Age never assigns ownership or authorizes execution. An interrupted linked attempt remains under its delivery's review policy; it is not automatically retried by the legacy scheduler or marked complete merely because a signal exists.

V93 adds analysis_not_before. A historical close arriving inside the existing interval live grace is HISTORICAL_DEFERRED until close+grace+1 ms. Only a later same-symbol/interval/candle live candidate may bypass that deferred row. Other earlier pending/running/review work remains a barrier. A completed live analysis covers deferred duplicates; if no eligible live close arrives, expiry permits historical-only analysis. A pre-existing signal without explicit completed work evidence requires review rather than being silently treated as a completed live execution. This does not fix collector FIX-133 and does not let repairs execute.

Proven's Collector delivery history shows approval provenance/reference, event-owned signal/work state/failure stage and historical deferral time. Recovery scans preserve their full-window query/filter/page semantics and now log [FIX-132][RECOVERY_SCAN] with fetched/returned counts, fetch time including pool acquisition and mapping, and instantaneous read-pool pressure. Latest per-symbol/interval measurements persist in shared_market_health. These are instrumentation, not measured production performance claims; no recovery query optimization is included.
