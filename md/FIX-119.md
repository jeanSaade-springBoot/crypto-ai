# FIX-119 — Accumulated-Evidence Late-Entry Timing Deferral

## Goal

Prevent an initial `ACCUMULATED_EVIDENCE` entry from executing at a price already classified as `LATE_ENTRY` when the accumulated evidence contains no BUY observation and the fresh 5m setup is not BUY/STRONG_BUY.

The opportunity is **not rejected**. It remains `BUILDING` so existing opportunity memory can re-evaluate later at better entry geometry or after fresh BUY confirmation appears.

## Evidence

The correction is based on direct Production wallet/signal evidence from 2026-09-06/07 KSA.

Bad accumulated entries that share the weak-authority + late-geometry pattern:

- BTCUSDT wallet trade #1701: `ACCUMULATED_EVIDENCE`, 0 BUY / 12 WATCH, 5m WATCH, 1h WATCH, Entry Quality 50 `LATE_ENTRY`.
- EDUUSDT wallet trade #1716: `ACCUMULATED_EVIDENCE`, 0 BUY / 16 WATCH, 5m WATCH, 1h BUY, Entry Quality 53 `LATE_ENTRY`.
- UNIUSDT wallet trade #1731: `ACCUMULATED_EVIDENCE`, 0 BUY / 7 WATCH, 5m WATCH, 1h WATCH, Entry Quality 50 `LATE_ENTRY`.

Protected profitable controls:

- ICPUSDT wallet trade #1702: `ACCUMULATED_EVIDENCE`, 0 BUY / 10 WATCH, 5m WATCH, 1h WATCH, Entry Quality 55 `ACCEPTABLE_ENTRY` — must remain executable.
- SUIUSDT wallet trade #1696: `ACCUMULATED_EVIDENCE`, 1 BUY / 11 WATCH, fresh 5m BUY, Entry Quality 50 `LATE_ENTRY` — must remain executable.

EDU is the control proving that a 1h BUY alone is not sufficient current timing authority to bypass this guard.

## Root cause

`ExecutionIntelligenceService.applyInitialEntryQualityGuard()` intentionally treats Entry Quality scores below 50 as chase entries that remain `BUILDING`, while scores 50–54 are classified `LATE_ENTRY` but remain executable with reduced initial allocation.

The recent-rejection Entry Quality penalty is also intentionally prevented from pushing an otherwise non-chase entry below the 50-point chase cutoff. Therefore accumulated WATCH evidence can remain executable even when the independent Entry Quality model already says the current price is late.

This is not a scoring defect. It is a mismatch between accumulated opportunity authority and current-price timing authority.

## Technical change

Only the existing `ACCUMULATED_EVIDENCE` initial-entry path is changed.

After the existing shared Entry Quality guard runs, FIX-119 calls `applyAccumulatedLateEntryTimingGuard(...)`.

The candidate is deferred only when all conditions are true:

1. the decision is already allowed;
2. the decision source is exactly `ACCUMULATED_EVIDENCE`;
3. Entry Quality classification is exactly `LATE_ENTRY`;
4. `evidence.buyCount() == 0`; and
5. fresh `evidence.fiveMinute()` is not BUY/STRONG_BUY.

The result becomes:

- state: `BUILDING`
- code: `ACCUMULATED_LATE_ENTRY_DEFERRED`
- source: `ACCUMULATED_EVIDENCE`
- position percent: 0 for the deferred action
- existing `Evidence` object preserved

`saveOpportunity()` is then called exactly through the existing path with the returned `BUILDING` decision, preserving the existing opportunity lifecycle and persisted evidence fields. No database column or migration is added.

## Intentionally unchanged

FIX-119 does not change:

- `Evidence` record fields or constructors;
- `EntryQuality` record fields, formula, thresholds or classifications;
- the `< 50` chase cutoff;
- rejection-zone scoring or its floor behavior;
- signal generation, score normalization or technical indicators;
- `IMMEDIATE_VALIDATION`;
- `SETUP_TIMEFRAME_ATR`;
- `SETUP_CONFIRMATION_WAKEUP`;
- recovery entries;
- progressive/confirmation adds;
- BUY/SELL thresholds;
- Stop Loss, Take Profit, Profit Lock or Near-TP logic;
- wallet execution semantics after a decision is allowed.

ICPUSDT 2026-09-06 17:36 KSA (the separate impulse/recovery-chase case) is explicitly outside FIX-119.

## Production / Replay parity

The guard lives in the shared `ExecutionIntelligenceService` path used by Production and Replay scope. No Replay-only branch or observer behavior is introduced.

## Observability

A defer writes:

`[FIX-119][ACCUMULATED_LATE_ENTRY_DEFERRED]`

with signal/symbol/time/price, Entry Quality, optional rejection-zone context, BUY/WATCH/NEUTRAL counts, evidence score/averages, 5m/1h context and `result=BUILDING`.

## Regression controls

Focused tests verify:

- BTC/UNI-style late WATCH-only accumulated authority defers;
- EDU-style 1h BUY does not bypass the guard when 5m is WATCH and accumulated BUY count is zero;
- ICP #1702 remains allowed because Entry Quality is `ACCEPTABLE_ENTRY`;
- SUI #1696 remains allowed because fresh BUY authority exists;
- non-`ACCUMULATED_EVIDENCE` authorities are structurally unchanged.
