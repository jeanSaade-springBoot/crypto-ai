# FIX-118 — Profit Lock TP-Extension Trace Instrumentation

## Status

Implemented as **Production/Replay observability only**. This phase does **not** change trading behavior.

## Confirmed mechanism

The current code has two Production Profit Lock evaluation/exit paths:

1. `LivePositionProtectionService` evaluates live market prices and can execute a mechanical Profit Lock exit.
2. `PaperTradingService` independently evaluates authoritative signal prices and can directly close through `closeFromProfitLock(...)`, including wallet execution.

Both route through the same `DynamicProfitLockService` / `ProfitLockPolicy`, which is the persisted writer of `highest_price_usdt`, `profit_lock_active`, `profit_lock_price_usdt`, `profit_lock_progress_percent`, and `profit_lock_activated_at`.

On a TP-extension tick, `LivePositionProtectionService` extends TP, persists it, and returns before Dynamic Profit Lock is evaluated on that exact tick. A previously active/locked state therefore survives into the next evaluation against the wider TP geometry.

Replay contains matching live-price and signal-price Profit Lock paths in `ShadowProductionReplayService`.

This instrumentation does not add the proposed `TP_EXTENSION_REBASE` state and does not change:

- Profit Lock activation/initial/trailing percentages
- TP extension eligibility or formula
- Stop Loss
- normal SELL authority
- hard-profit-floor behavior
- wallet execution
- FIX-117 Near-TP behavior
- Replay baseline trading semantics

The behavioral FIX-118 correction remains subject to the separately approved technical design after these traces are reviewed.
