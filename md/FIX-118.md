# FIX-118 — Profit Lock TP-Extension Rebase

## Status

Implemented as an **intentional Production/Replay trading-semantic correction** after the observability phase confirmed the defect.

## Confirmed defect

Dynamic Profit Lock can legitimately activate and advance under the pre-extension take-profit geometry. When price reaches the old TP, continuation can approve a wider TP and return before Profit Lock evaluates that same extension tick. On the next evaluation, progress is recalculated against the wider target and may be below the configured activation threshold, but the legacy `profit_lock_active` / `profit_lock_price_usdt` values remain sticky. The old lock can therefore execute even though the position no longer qualifies for Profit Lock activation against the newly approved TP.

Primary evidence:

- ICPUSDT #1010: old TP `2.719244613453` extended to `2.728866920180`; the historical lock `2.711546768072` then exited the position before the extended TP was subsequently reached.
- ICPUSDT #1014: repeated TP extensions preserved a lock earned against superseded geometry, culminating in an early Profit Lock exit after four approved extensions.

## Behavioral correction

FIX-118 adds persisted `ProfitLockState`:

- `INACTIVE`
- `ACTIVE`
- `TP_EXTENSION_REBASE`

Invariant:

- `ACTIVE` means the persisted lock is executable.
- During `TP_EXTENSION_REBASE`, legacy `profit_lock_active` remains `true` because protection was historically earned, but the explicit state is the sole execution authority and the old lock is non-executable.

### TP extension transition

When continuation approves a new TP:

- `INACTIVE` remains `INACTIVE`.
- `ACTIVE` remains `ACTIVE` if best progress against the new TP is still at/above the configured activation threshold.
- `ACTIVE` becomes `TP_EXTENSION_REBASE` if new-geometry progress falls below activation.
- `TP_EXTENSION_REBASE` remains in rebase across repeated extensions until current-TP activation is earned again.

The historical lock price is preserved while rebasing; it is not used as an exit trigger.

### Rebase release

During rebase, highest price and progress continue to update against the current TP. Once best progress reaches the configured activation threshold (70% by current Administration defaults), the position returns to `ACTIVE`. Normal `ProfitLockPolicy` logic then resumes against the current geometry and the rebase timestamp is cleared.

### Safety authorities

Stop Loss remains absolute and retains priority.

While `TP_EXTENSION_REBASE` is active, the superseded lock is non-executable, but a standalone protected-profit safety floor remains active at:

`entry × 1.0005`

If price breaches that floor, Production/Replay exits with `PROFIT_LOCK_HARD_EXIT` without requiring the old Profit Lock to trigger first.

Normal thesis/signal exits remain available during rebase because `DynamicProfitLockService.Evaluation.active()` is `false` while the state is `TP_EXTENSION_REBASE`.

## Persistence / migration

Migration `V82__fix_118_profit_lock_tp_extension_rebase.sql` adds:

- `wallet_managed_position.profit_lock_state`
- `wallet_managed_position.profit_lock_rebase_started_at`
- matching Replay columns in `wallet_position_test`
- matching archive columns in `wallet_position_test_archive`

Mandatory backfill maps existing rows as follows:

- `profit_lock_active = 1` → `ACTIVE`
- otherwise → `INACTIVE`

This prevents deployment/restart from forgetting historically earned protection.

## Production paths

Both real Production Profit Lock authorities honor the explicit state:

1. `LivePositionProtectionService` live-price protection.
2. `PaperTradingService` authoritative signal-price protection.

Both enforce the standalone rebase safety floor while suppressing execution of the superseded lock.

## Replay parity

`ShadowProductionReplayService` persists and evaluates the same three-state Profit Lock lifecycle for live-price and signal-price fallback paths. Replay TP extension, rebase, release, hard-floor exit, and active-lock triggering use the same state semantics as Production.

## Preserved behavior

FIX-118 does **not** change:

- Profit Lock activation percentage
- initial protected percentage
- trail-step percentage
- TP-extension eligibility
- TP-extension formula
- Stop Loss geometry
- normal signal/thesis exit policy
- FIX-117 Near-TP state behavior
- BUY rules, sizing, Entry Quality, market context, or Execution Intelligence
- FIX-119 accumulated-evidence entry timing behavior

## Observability

Existing FIX-118 Production/Replay traces remain and now include explicit state/rebase information. Additional hard-floor traces identify exits during rebase.

## Historical regression coverage

The production-behavior implementation is locked by direct regressions in addition to the general state-machine tests:

- `fix118HistoricalIcp1010ExtendedTpMakesOldLockNonExecutableAtActualExitPrice`
  - entry `2.700`
  - old TP `2.719244613453`
  - extended TP `2.728866920180`
  - historical lock `2.711546768072`
  - historical exit price `2.710`
  - proves the superseded lock is non-executable while the protected-profit floor is not breached.
- `fix118HistoricalIcp1014FourthExtensionMakesOldLockNonExecutableAtActualExitPrice`
  - entry `2.727`
  - prior TP `2.805802860771`
  - fourth extended TP `2.845204291157`
  - historical lock `2.774281716463`
  - historical exit price `2.766`
  - proves the fourth-extension case remains in rebase and does not execute the superseded lock.
- `fix118RepeatedExtensionWhileAlreadyRebasingKeepsOriginalRebaseTimestamp`
  - reproduces consecutive #1014-style TP extensions and proves rebase remains active without resetting the original `profit_lock_rebase_started_at`.
- `normalSellAuthorityRemainsAvailableDuringRebase`
  - proves a normal thesis/SELL exit remains executable while the superseded Profit Lock is non-executable and the hard floor is not breached.

These tests are regression locks for FIX-118 behavior; they do not add or change trading semantics.
