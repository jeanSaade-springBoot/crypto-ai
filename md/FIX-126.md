# FIX-126 — Preserve complete wallet execution explanations

Status: CANDIDATE IMPLEMENTED; Maven/JUnit and MySQL migration validation pending.

## Confirmed defect

At 2026-09-08 02:14:23 UTC+02:00 crypto-ai-trader failed to persist wallet BUY signal #634982 because execution_message exceeded the database's VARCHAR(1000). The supplied schema confirms that limit, and the supplied wallet query returns no trade for that signal. The BUY path adds wallet metadata to the execution explanation and price details without limiting the concatenated message. The subsequent ICP recovery rollback is consistent with the same persistence failure.

## Scope

V85 changes wallet_trade.execution_message to nullable MEDIUMTEXT with the existing utf8mb4_unicode_ci collation. WalletTrade's Java column mapping matches. Existing audit text is retained; no truncation or synthetic replacement is introduced. MEDIUMTEXT provides substantially more room but is not unlimited.

No execution service or BUY/SELL decision formula changes. Longer already-approved executions can now persist rather than fail because of their explanation length. Both BUY and SELL messages use the shared column. No historical failed trade is replayed, backdated or inserted. FIX-122 diagnostics do not directly append to this message and are not identified as its cause.

Existing trade reporting continues to show the stored message. No new per-trade log is added solely for a column change: Flyway records the FIX-126 migration and existing execution logs continue. FIX-124 adds its own separate incident diagnostics and review UI.
