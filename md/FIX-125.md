# FIX-125 — Wallet transaction coordination through commit

Status: PLANNED — TO BE DONE. Number reserved; no runtime implementation in this update.

## Finding

The synchronized wallet BUY/SELL method can release its monitor before the surrounding Spring transaction commits. This is a structurally possible race window, not a reproduced failure or a proven cause of the reported deadlocks.

FIX-122 uses committed reads and rechecks its boundary at execution-price approval. Those checks do not keep synchronization effective through wallet commit and do not eliminate the remaining race window.

## Planned scope

1. Reproduce monitor release versus transaction completion with a deterministic concurrency test, using controlled coordination rather than sleep-based timing assumptions.
2. Design coordination for the relevant wallet BUY/SELL paths through transaction completion, including rollback and exception cleanup. Review transaction propagation and existing callers before choosing the mechanism.
3. Test concurrent BUY/SELL ordering, commit visibility, rollback, failure cleanup and preservation of existing wallet authority. Verify corresponding Replay decision behavior without importing Production state.
4. Add implementation logs, Java comments, relevant persisted diagnostics and actual Maven/JUnit results when this fix is implemented.

Keep FIX-123 (ATR sizing review) and FIX-124 (reported deadlock investigation/repair) separate. Do not add a database row lock or claim a deadlock repair without evidence and reviewed scope. Reserving this number does not imply that FIX-125 is implemented, tested or enabled.
