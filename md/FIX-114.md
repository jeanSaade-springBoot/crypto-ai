# FIX-114 — System Health scheduled/background job inventory

## Scope

Read-only observability enhancement. The System Health page now shows one compact table containing only the eight recurring jobs requested by Operations.

## Golden rule

**Replay = Production.** FIX-114 does not modify Production or Replay business logic, scheduler cadence, trading thresholds, signal generation, execution ordering, or parity behavior.

## Implementation

- `ScheduleConfigurationService.healthScheduledJobs()` exposes runtime cadence and enabled state from the same configuration objects used by the jobs.
- `GET /api/system-health/scheduled-jobs` is read-only.
- `system-health.html` renders columns: `#`, `Job`, `Schedule`, `Enabled`, `Purpose`.
- `system-health.js` reloads the job inventory when System Health is refreshed.
- No start, stop, enable, disable, or reschedule action is exposed.

## Jobs shown

1. `ScheduledAnalysisService.analyzeConfiguredSymbols()`
2. `OrderBookLiquidityService.collectConfiguredOrderBooks()`
3. `SentimentCollectionService.collectScheduled()`
4. `FundamentalCollectionService.collectConfiguredSymbols()`
5. `WhaleCollectionScheduler.collect()`
6. `WhaleEvaluationScheduler.evaluate()`
7. `WhaleAggregationScheduler.aggregate()`
8. `BinanceWebSocketManager` health/reconnect loop

Note: the actual Order Book scheduled method in this project is `collectConfiguredOrderBooks()`, so Health displays the real method name rather than an alias.
