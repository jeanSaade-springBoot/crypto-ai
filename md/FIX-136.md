# FIX-136 — Trader audit transaction isolation and UTC connection alignment

## Evidence and scope
The production log shows audit INSERT failures in `CandleInputAudit.capture` during `CandleDataQualityService.validate`, a read-only local JPA transaction. Five sampled first analyses failed before signal registration. Database inspection found 105 REVIEW_REQUIRED analyses with no attributed signal work and one blocked lane for each of 21 symbols × 5 intervals. The same-source-event comparison independently proves a -7200-second stored timestamp shift.

## Change
LIVE and Replay explicitly pass the application's local transaction manager to the audit scope. Each audit INSERT executes in a writable REQUIRES_NEW transaction, suspending and restoring the outer transaction and its connection. Evidence commits independently and can remain after the caller fails: an audit row proves inputs were read, not that analysis or execution completed. Hash format and input order are unchanged. Errors propagate; they are never swallowed to allow unaudited execution. The legacy two-argument scope overload remains for standalone JDBC tests; production JPA callers use the three-argument overload.

The collector reader stays read-only. No writes go to collector tables. Audit transactions use the existing local pool and borrow an additional connection while the outer connection is suspended. SQL timeout is five seconds; pool checkout retains its existing 30-second limit (not an end-to-end deadline). Pool contention remains possible under saturation and must be observed; this patch does not solve shared-reader query timeouts or promise zero latency. Do not increase worker concurrency without measuring local pool headroom.

Local Hikari connections explicitly set UTC at both JDBC and MySQL session levels. `serverTimezone=UTC` alone does not force the server session timezone. Hibernate's existing UTC setting is retained. This affects future local reads/writes, so persisted timestamps must be reconciled before enabling the corrected consumer against prior shifted state. No global MySQL or collector timezone changes.

Worker failures now retain an exception summary in the delivery row, without resetting owner tokens or phases. An audit-specific log includes context and read index. Existing scoring, thresholds, eligibility checks, wallet coordination, and Replay business rules are unchanged.

## Tests actually run
`md/test-evidence/FIX-136-mysql.log`: three standalone scenarios passed using MySQL 8.0.44, Hibernate and Spring JpaTransactionManager. Both LIVE and Replay write evidence inside a real read-only outer JPA transaction; the inner audit commits independently, the outer connection/read-only state is restored, and evidence survives an outer rollback. Missing-table audit failure propagates and cleans up the context. The test uses an isolated `fix136_test` database, never production.

The production audit class and standalone harness compiled under Java 21. Full Maven/JUnit could not run: Spring Boot parent 4.1.0 is unavailable in this workspace's offline Maven cache. Raw failure retained. Added `CandleInputAuditTransactionTest` for Jenkins; not claimed as executed locally. Remaining changed production files require the full Jenkins build. MySQL test is 8.0.44, whereas production is 8.4.

## Apply and restart sequence
1. Trader remains stopped; Collector remains running. Merge this patch's listed files into the latest Trader source. Do not replace the repository wholesale with an older baseline. Jenkinsfile/deployment scripts are intentionally absent from the patch.
2. The current Jenkins job automatically starts LIVE after building. Do not trigger it until reconciliation is prepared. Build/test without its deployment stage first.
3. Run `md/sql/FIX-136-recovery-preflight.sql` read-only and retain results. The two-hour shift may affect delivery candle times, observation/receipt times, market-price evidence, consumer watermarks and approval metadata. Do not assume all tables/columns have identical corruption.
4. Reconcile by immutable source_event_id, validate symbol/sequence/interval, preserve original evidence. Never blindly add two hours to all tables. Do not rewrite collector history, approvals or wallet records as a shortcut.
5. Do not reset completed protection or rewind discovered_sequence. An empty source_event_id join alone does not establish absence of every possible effect. Only audited, confirmed pre-business failures may be released from REVIEW_REQUIRED; old closes must remain subject to freshness/historical gates. Quarantine ambiguous outcomes.
6. Start one corrected Trader only after the persisted-state correction is reviewed. Verify exact timestamp equality for newly imported source IDs, progressing closed-candle analysis, no audit read-only failures, and pool/latency behavior. Keep crypto_ai.candle unrenamed.

No production data mutation or automatic recovery migration is included. The dashboard query timeout remains separately unresolved.
