# FIX-117 — Preserve Earned Near-TP Protection Across TP Extension

## Classification
Narrow Production/Replay position-protection correction. No changes to entry logic, continuation eligibility, BUY/SELL thresholds, harvest thresholds, harvest sizing, stop loss, Dynamic Profit Lock, or normal exit rules.

## Confirmed problem
ENAUSDT position #978 earned FIX-11T Near-TP protection against its original TP, then the continuation policy legitimately extended the TP. The pre-FIX-117 extension path reset every unharvested Near-TP state to `INACTIVE`, erasing already-earned protection. The wider target was not re-armed before the later reversal and the position ultimately reached stop loss.

## Frozen behavioral rule
- `INACTIVE`: existing reset behavior remains unchanged.
- `NEAR_TP_ARMED`: preserve state and `nearTpBestPrice` exactly.
- `NEAR_TP_REJECTION_DETECTED`: preserve state and `nearTpBestPrice`; clear `nearTpBearishStreak` and `nearTpLastOneMinuteSignalId` because that evidence was accumulated under the old geometry.
- `NEAR_TP_FAILURE_CONFIRMED`: retain existing reset-to-`INACTIVE` behavior. Its interruption/recovery lifecycle is deliberately out of scope.
- `NEAR_TP_PARTIAL_HARVESTED`: preserve existing terminal behavior.

`NearTpFailureProtectionPolicy` already recalculates planned distance from the current take-profit on every evaluation, so historical best price remains a valid market observation and does not require rebasing.

## Production
`LivePositionProtectionService.resetNearTpTrackingForNewRiskGeometry()` implements the frozen rule above. Only ARMED and REJECTION_DETECTED change from the pre-fix behavior.

## Replay parity
`ShadowProductionReplayService.ShadowPosition.withTakeProfit()` implements the same state transitions. Progressive-add geometry reset behavior is unchanged.

## Regression coverage
`Fix117NearTpExtensionStateTest` verifies:
1. ARMED survives extension and keeps exact best price.
2. REJECTION_DETECTED survives extension, clears old bearish evidence, and naturally recovers when recalculated giveback falls below 20%.
3. REJECTION_DETECTED remains rejected when recalculated giveback stays at or above 20%, with a clean evidence streak.
4. INACTIVE keeps existing reset behavior.
5. FAILURE_CONFIRMED keeps existing reset behavior.
6. Production and Replay produce identical TP-extension state transitions for all Near-TP states.

Existing `NearTpFailureProtectionPolicyTest` coverage remains unchanged.

## Separate FIX-074 test-wiring correction
The unrelated `ScheduledAnalysisServiceTest` compilation failure introduced when FIX-074 added `CandleAnalysisExecutionCoordinator` is corrected only in test wiring by supplying a real coordinator instance to both test constructor calls. Production FIX-074 code is unchanged.
