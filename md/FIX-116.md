# FIX-116 — System Health request deduplication and diagnostic query protection

## Problem
The global System Health badge polls `/api/system-health/daily` every 60 seconds. Under database load the read-only daily/baseline diagnostics can take longer than one interval. The browser previously started another request regardless, allowing identical heavy diagnostic queries to overlap and compete for the same DB pool used by interactive Dashboard endpoints.

## Changes
- `global-system-health.js` now has an in-flight guard. A 60-second tick is skipped while the previous request is unresolved; `finally` always releases the guard.
- `SystemHealthDailyService.dailyHealth()` now keeps a short 45-second completed-result cache and serializes cache misses. Concurrent callers therefore share one calculation instead of executing the same 7-day diagnostics in parallel.
- Added `V75__catching_market_summary_lookup_index.sql` so the Catching Market 1h/4h/24h summary can begin from its `end_time` lookback range instead of relying on indexes whose leading column is symbol/review status.
- Added Maven regression coverage for cache reuse and concurrent single-flight behavior.

## Safety boundary
This fix changes read-only observability/query resource usage only. It does not change Order Book collection/evaluation, Catching Market detection, signals, FinalDecision, execution, wallet behavior, scheduler business logic, or Replay evaluation. Replay = Production remains unchanged.
