## Candidate change and explicit behavioral effects

BinanceKlineService now requires no ambient transaction. KlineTransactionCoordinator performs sequential independent transactions:

1. Persist the candle and, for the canonical 1m stream, its exact price observation together; commit before acquiring any position lock.
2. Evaluate the existing live-protection business logic in a fresh transaction. Only a MySQL 1213/40001 thrown by the FIRST managed-position lookup receives a retry marker. After rollback, allow one immediate retry (two attempts total). No retry of later decision, wallet, observer or ambiguous commit failures.
3. Persist a RECOVERED or FAILED incident for a retried/failed evaluation in a separate bounded transaction. A normal tick creates no diagnostic row. RECOVERED means evaluation committed, not necessarily that a SELL executed.
4. Run the existing debug observer independently. Its rollback cannot undo input or protection.
5. Publish a closed-candle event inside a new transaction after protection finishes, retaining the existing AFTER_COMMIT listener and protection-before-dispatch ordering.

An exhausted or nonretryable protection failure retains the input and allows closed-candle dispatch; the incident remains visible. If input persistence itself fails, protection and dispatch are not invoked. This intentionally prevents protection from consuming an input that failed to persist. No delayed background replay of failed price ticks is introduced.

These are Production transaction/recovery changes. A previously failed initial check can now succeed, so actual executions can differ during contention. Input becomes visible to other database readers earlier, and a protection commit is retained even if the later observer or dispatch fails. The split no longer provides one all-or-nothing kline/protection transaction. A process crash after input commit but before protection/dispatch can leave committed input without that evaluation; durable exactly-once tick processing is not introduced by this patch. No score, threshold, sizing, exit formula, price fallback or wallet authority is changed. Exact symbol + interval + candle_open_time lineage and Binance observed time remain intact.
