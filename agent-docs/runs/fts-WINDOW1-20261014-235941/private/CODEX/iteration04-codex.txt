## FINDINGS

- **PROJECT EVIDENCE:** The frozen cohort remains exactly `paper_position` IDs **182, 172, 162, 158, 143, 137**. No substitution was made.

- **PROJECT EVIDENCE:** Current source establishes the authoritative linkage route as `paper_position.signal_id` → `wallet_managed_position.entry_signal_id`, with `production_exit_audit.paper_position_id` recording the terminal paper-position audit and its `wallet_position_id`. Numeric equality between a frozen `paper_position.id` and a logged `wallet_managed_position.id` is not a valid join.

- **PROJECT EVIDENCE:** Entry route:

```text
closed candle → TradeSignal → signal_processing_work claim/freshness
→ buy validation + canonical execution price
→ wallet BUY / managed position → paper_position OPEN
```

  `PaperTradingService` obtains a fresh canonical execution price, executes the wallet BUY, then creates `paper_position` with that price and the execution signal. `wallet_trade.execution_price_observed_at` is the entry-price timing evidence.

- **PROJECT EVIDENCE:** Live-price protection route:

```text
market_price_event PENDING → managed-position lock/freshness/order check
→ TP / SL / profit-lock / confirmed signal-exit policy
→ mechanical wallet exit + paper close + exit audit
→ market_price_event APPLIED on transaction commit
```

  `APPLIED` proves the protection callback committed; it does not alone prove that a particular frozen paper position changed, because a no-position callback can also complete.

- **PROJECT EVIDENCE:** Signal-driven and live-price exits are distinct. Signal processing can close from a fresh authoritative signal price; live protection acts on accepted observed prices. Their priority order is not identical, so a close reason cannot be inferred from a candle or from a later signal.

- **PROJECT EVIDENCE:** A live-price closure updates `paper_position` but does not set `exit_signal_id`; its source signal is retained in `production_exit_audit`. Therefore a null `exit_signal_id` must not be interpreted as “no exit context” or “manual close.”

- **PROJECT EVIDENCE:** `paper_position.realized_pnl` is calculated from entry/exit and remaining quantity, preserving prior partial-harvest P&L. Fee reconciliation must use `wallet_trade`; paper-wallet routes currently persist `fee_usdt=0`, but that is still evidence to verify rather than assume.

- **AGENT INFERENCE:** The prior candidate logs for wallet position IDs 137, 143, 158, 162, 172, and 182 remain unlinked to the frozen paper-position cohort. They cannot support a cause, exit route, symbol, or timeline conclusion until the durable joins below confirm them.
