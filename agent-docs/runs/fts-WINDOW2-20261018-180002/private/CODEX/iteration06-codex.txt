- The project has documented a historical reconnect-boundary failure mode: a missing final closed-kline event can leave candle evidence incomplete and block later analysis. That is a known system risk, **not evidence that any of the six frozen trades was affected**.

**EXTERNAL RESEARCH**

- Binance’s official kline stream documentation describes updates to the current candle and an explicit `x` flag denoting whether the candle is closed; its payload timestamps are UTC. This supports the project’s need to distinguish an observed closed candle from a merely updating candle, but does not establish any historical condition for these trades. [Binance kline stream documentation](https://developers.binance.com/zh-CN/docs/products/spot/testnet/web-socket-streams)

**AGENT INFERENCE**

- No individual loss can be attributed to a strategy defect, late/chase entry, stale-data event, missed protection trigger, fee/accounting issue, or exit-policy decision without the authoritative row and linked evidence.
- Each loss needs this causal test, in order:

  `paper_position lifecycle → linked entry/exit signal → wallet BUY/SELL reconciliation → accepted price-event/protection evidence → contemporaneous candles/signals`

- A negative `realized_pnl` alone proves only that the row belongs to the frozen failed-trade selection.
- The supplied snapshot metadata remains internally inconsistent: `2026-10-18 15:00:04 UTC` converts to `18:00:04 KSA`, whereas the supplied snapshot states `18:00:02 KSA`. I retain both supplied values; no trade timestamp is presently available to report in KSA.

### DB_REQUEST

QueryId: DBQ-CODEX-I6-001  
Purpose: Obtain the deployed schema and authoritative lifecycle rows for exactly the six frozen positions, while independently re-proving the frozen selection. This is prerequisite evidence for root-cause classification; all reads are bounded and confined to `crypto_ai`.

SQL:
```sql
SELECT
    table_name,
    ordinal_position,
    column_name,
    column_type,
    is_nullable,
    column_key
FROM information_schema.columns
WHERE table_schema = 'crypto_ai'
  AND table_name IN (
      'paper_position',
      'trade_signal',
      'wallet_trade',
      'wallet_managed_position',
      'market_price_event',
      'production_exit_audit',
      'position_management_event',
      'signal_processing_work',
      'candle',
      'technical_indicator'
  )
ORDER BY table_name, ordinal_position
LIMIT 1000;

SELECT p.*
FROM crypto_ai.paper_position p
WHERE p.id IN (182, 172, 162, 158, 143, 137)
ORDER BY FIELD(p.id, 182, 172, 162, 158, 143, 137)
LIMIT 6;

SELECT
    id,
    status,
    closed_at,
    realized_pnl
FROM crypto_ai.paper_position
WHERE status = 'CLOSED'
  AND closed_at IS NOT NULL
  AND realized_pnl < 0
ORDER BY closed_at DESC
LIMIT 6;
```
