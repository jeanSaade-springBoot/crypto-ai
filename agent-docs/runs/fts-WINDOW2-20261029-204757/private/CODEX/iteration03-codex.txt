- **PROJECT EVIDENCE:** The runtime order is input transaction → protection transaction → observer transaction → close-dispatch transaction. Protection timing can be correlated only indirectly through symbol and `observed_at`; it cannot by itself attribute latency to one frozen paper position. [KlineTransactionCoordinator.java](/C:/workspace/crypto-ai-trader-mysql/src/main/java/com/crypto/infrastructure/transaction/KlineTransactionCoordinator.java:35)

- **PROJECT EVIDENCE:** A `paper_position` is saved closed before the wallet-exit attempt; a caught wallet exception does not reopen it. Thus a closed negative-P&L row is not proof of a financially committed wallet exit. The corresponding managed-position and wallet-trade evidence is required. [PaperTradingService.java](/C:/workspace/crypto-ai-trader-mysql/src/main/java/com/crypto/service/PaperTradingService.java:501)
