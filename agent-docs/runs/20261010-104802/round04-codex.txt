- **[PROJECT EVIDENCE]** A REST import can finalize a live `closed=0` candle as `BACKFILL` without a runtime close token. If the final WebSocket kline arrives afterward, it is treated as `DUPLICATE_CLOSE`, publishes no close event, the OFF-mode detector excludes it, and scheduled recovery bypasses OFF mode. This leaves no analysis or durable analysis outcome for that identity.

- **[PROJECT EVIDENCE]** Default database Replay can include an unclosed candle. Its snapshot query only uses closed candles, so Replay can generate a later duplicate of the preceding closed candle’s signal identity. Production’s close-event worker rejects this identity mismatch and checks for an existing signal.

- **[AGENT INFERENCE]** That Replay defect is conditional on the requested range including a row still open at Replay load time. It is not look-ahead, but can create late duplicate context and potentially a shadow decision Production could not make.
