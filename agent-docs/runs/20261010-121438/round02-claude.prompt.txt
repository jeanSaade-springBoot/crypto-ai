**External research** (none of it is evidence about live trading performance)
- **[ER-1] Martin Fowler, ["The LMAX Architecture"](https://www.martinfowler.com/articles/lmax.html), 12 July 2011.**
  - Findings: every input event is written to a durable journal before the business logic processes it; state can be rebuilt by replaying those inputs; the business logic makes no external calls, and external results come back as new input events.
  - Limitations: LMAX's core is single-threaded and in memory. This project's thread and lock ordering cannot be reproduced the same way.
  - Relevance: supports R-04 and R-09. Record each external context result when it is consumed. The context columns on `trade_signal` are already a partial journal of results.
- **[ER-2] Binance Developers, ["WebSocket Streams"](https://developers.binance.com/docs/binance-spot-api-docs/web-socket-streams) (Spot) and its [legacy copy](https://developers.binance.com/legacy-docs/binance-spot-api-docs/web-socket-streams).** No date shown.
  - Findings: each kline message carries `E` (event time), `t`/`T` (open and close times) and `x` (closed flag). Updates arrive every 2000 ms for intervals other than 1s. A connection lasts at most 24 hours.
  - Limitations: the docs don't say how far the closing message's `E` trails `T`. I saw the payload only through legacy and testnet copies.
  - Relevance: this is the mechanism behind F5 and R-14.
- **[ER-3] Binance Developers, ["Filters"](https://developers.binance.com/docs/binance-spot-api-docs/filters).** No date shown.
  - Findings: `MIN_NOTIONAL` and `NOTIONAL` set the minimum (and maximum) order value and are published through `exchangeInfo`. No historical or as-of lookup is documented.
  - Limitations: the absence of a documented endpoint is not proof that no history exists anywhere.
  - Relevance: R-24.
- **[ER-4] Bailey, Borwein, López de Prado and Zhu, ["The Probability of Backtest Overfitting"](https://papers.ssrn.com/abstract=2326253), Journal of Computational Finance, 2015/2017.**
  - Findings: choosing among many backtests overstates real results, and hold-out testing is unreliable for this.
  - Limitations: the paper is about strategy performance, not code parity. I relied on the abstract and summaries only.
  - Relevance: the windows in RPR-T-11 must not be curated to pass; report refusal and mismatch rates (R-33).
