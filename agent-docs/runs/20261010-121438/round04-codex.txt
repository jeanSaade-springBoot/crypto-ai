## OBJECTIONS

- **PROJECT EVIDENCE:** Reject the response as a sufficient requirements basis. It drops the pre-write contradiction, does not require a complete no-I/O/side-effect inventory, and leaves wallet isolation incompatible with execution/lifecycle claims.

- **AGENT INFERENCE:** The next single specification must obtain these user decisions before authorizing a design:
  1. Parity target: frozen working tree or evidenced deployed JAR/configuration per window.
  2. Isolation boundary: absolute prohibition on Production wallet/position reads, or named read-only oracle/evidence reads.
  3. Permitted claim tiers: analysis parity, execution-decision parity, lifecycle parity, or simulation.
  4. No-look-ahead treatment for recovered/historical signals and unavailable context.
  5. Single-symbol first versus fully specified multi-symbol account scheduling.
  6. Default mode and each Replay-only retirement.

- **PROJECT EVIDENCE:** The next specification must include a master registry for:
  - preflight qualification before business-output writes, with a narrowly defined refusal audit record and a no-write regression test;
  - per-tier oracle records: source identity, as-of time, availability time, equality rule, missing-evidence result, and account-state eligibility;
  - immutable price-event IDs, ordering slots, source era, close-message linkage, accepted-stream coverage, tie/refusal rules, and separate signal-price mechanics;
  - full orchestration: protection, signal exits, price authority, fill/open-time clocks, expiry/retry/rollback outcomes, daily-budget creation timing, daily-loss failure, global caps, progressive adds, and stop-history boundary;
  - field-by-field context handling for derivatives, order book, sentiment, BTC, and higher timeframes: inject persisted evidence, recompute from sufficient as-of evidence, or refuse;
  - deny-by-default external I/O and side effects, including HTTP, mutable wallet settings, shared-table writes, and in-process metrics;
  - baseline/deployment/configuration/era rules, including V106–V109 and the FIX-154 source/document discrepancy;
  - Production impact, transaction/latency analysis, rollback, resource/cancellation safeguards, and disposable-MySQL validation;
  - explicit refusal/mismatch-rate reporting and documentation updates only after implementation becomes authorized.
