## FINDINGS

1. **Implemented default is trader-owned local ingestion, not the pending-only direction.** Checked-in `shared-market.mode` defaults to `OFF`; in OFF the trader starts Binance WebSocket ingestion, performs REST bootstrap/import, and persists to its local `crypto_ai.candle`.

2. **LIVE retains collector ownership.** In LIVE, trader WebSocket and REST ingestion throw/return early, candle reads route through the collector read pool targeting `crypto_ai_v2`, and local writes are rejected.

3. **OBSERVE is an architectural contradiction.** It is not collector-only:
   - Direct trader WebSocket and REST ingestion remain enabled because their guard is only `LIVE`.
   - It also creates a read-only collector pool and the shared consumer polls collector tables.
   - Bootstrap may generate `STARTUP` signals and call paper-trading processing in OBSERVE.
   - The direct-price pending resolver is OFF-only, so direct 1m OBSERVE events can remain `PENDING`, causing Replay to reject parity claims.

   The other report’s statement that OBSERVE “trades exactly as OFF” is too strong: code establishes that it can enter the analysis/paper-trading path, but a completed trade still depends on downstream strategy/risk/execution gates not traced here.

4. **Runtime close handling has the intended basic shape.** The runtime upsert assigns a close token only for an open→closed transition. The successful token-owning receipt publishes after input → protection → observer ordering, and async dispatcher work occurs after commit.

5. **Ordinary REST import violates the pending recovery/backfill contract.** Its `BACKFILL` duplicate-key clause can finalize an existing `closed=0` candle. It preserves provenance and adds no token, no analysis outcome, and no dispatch. Therefore a candle left open during shutdown can be closed by bootstrap before WebSocket startup and become ineligible for both normal token dispatch and reconciliation (which selects only `closed=0` rows).

6. **The implemented reconciliation slice is safer than ordinary REST import, but disabled and incomplete.** It is OFF-only and disabled by default. Its recovery SQL is update-only for existing open rows; gap repair is insert-if-absent; both produce `SKIPPED_NOT_LIVE` outcomes when successful. However:
   - candidate selection applies `LIMIT 50` before due/loss-evidence filtering;
   - only active-window candidates are selected, so a transient `PENDING` candidate that ages out is no longer selected and has no terminal age-out path;
   - no shared REST rate-limit/ban policy was found.

7. **Replay is not proven to reproduce the local live-admission boundary.** Replay loads any `closed=1` candles by time/identity, without filtering by runtime provenance, close token, reconciliation outcome, or historical-only status. It does correctly reject unresolved `PENDING` price evidence, but that is narrower than candle-admission parity.

8. **Fresh trader-only installation remains unresolved.** The applied Java migration `V103` explicitly fails unless `crypto_ai_v2.market_data_stream_event` exists, contradicting a fully collector-independent fresh bootstrap.

9. **Documentation conflicts with code and with itself.**
   - `AGENTS.md` calls local-candle runtime a pending design, while code defaults to OFF and both architecture documents say FIX-153 is implemented in source but unapproved.
   - `claude-docs` says direct ingestion is disabled in both LIVE and OBSERVE; code disables it only in LIVE.
   - `codex-docs` accurately describes ordinary REST finalization, but its adjacent “pending reconciliation” narrative is stale relative to the implemented, disabled reconciliation slice.
   - `CandleRepository` claims REST backfill “inserts missing identities only,” contradicted by its duplicate-key update SQL.

## OBJECTIONS

- Current default source configuration realizes much of the pending direction, but does not meet its release contract.
- Bootstrap REST can silently consume a runtime close without durable admission/outcome evidence.
- Disabled reconciliation cannot supply the required automatic recovery; its current retry/window behavior does not guarantee terminal resolution.
- OBSERVE simultaneously permits direct ingestion and collector connectivity, contrary to the required separation.
- No code evidence establishes shared Binance 429/418, `Retry-After`, or request-budget handling across bootstrap, reconciliation, and clock operations.
- Replay parity for provenance/outcome-based local candle admission is unproven.
- A collector-free fresh Flyway bootstrap is blocked by V103.
