## FINDINGS

1. The checked-in default is trader-owned ingestion: `shared-market.mode=OFF`. In OFF, Binance WebSocket kline processing writes local `crypto_ai.candle`; REST bootstrap/import also writes that local table.

2. The collector/shared-market path is still implemented. In `LIVE`, the trader opens a read-only connection to `crypto_ai_v2` and consumes `market_data_stream_event` / `market_data_stream_cursor`. In `OBSERVE`, it also creates that external connection and starts shared-market schedulers.

3. `OBSERVE` is a real dual-path contradiction. Direct WebSocket and REST paths are disabled only when mode is `LIVE`; shared consumer work runs whenever mode is not `OFF`. Thus OBSERVE can use both direct Binance ingestion and the collector path. Further, its bootstrap falls through to analysis and `PaperTradingService.processSignal`, so imported historical candles can produce STARTUP paper processing.

4. Runtime WebSocket candle writes are materially safer than REST import: runtime upsert is monotonic and assigns a close-transition token only on an open-to-closed transition. The input → protection → observer → close-dispatch order is preserved, and event dispatch occurs after commit.

5. Ordinary REST import/backfill violates the pending local-candle recovery direction. The generic `BACKFILL` duplicate-key SQL can finalise an existing open runtime candle, while preserving its existing null token. It therefore creates neither a normal close admission nor recovery audit/outcome evidence. The code comment saying backfill “inserts missing identities only” is contradicted by the SQL.

6. This substantiates a live-close admission hole: REST can close a runtime-open candle before the final WebSocket event. The later WebSocket event cannot transition it or mint a token; the detector requires a token; reconciliation selects only `closed=0`; gap discovery skips identities already present. The candle can therefore remain closed without normal analysis admission.

7. A specialized reconciliation service exists and is closer to the pending design: after grace/finality it either finalizes an existing open candle or uses insert-if-absent for a gap, records reconciliation audit state and a non-live outcome, and does not dispatch analysis. However, it is disabled by default. Its open-candidate query applies `LIMIT 50` before due/loss-evidence filtering and does not filter enabled symbols in SQL.

8. I correct the earlier assertion that a `trade_signal` row alone proves completed processing. `AnalysisService.analyzeForProcessing` registers signal-processing work in the same transaction as signal creation. That part is atomic. However, interrupted `RUNNING` work is explicitly moved to `REVIEW_REQUIRED` with “no automatic replay.” I did not find an OFF-mode resolver that automatically concludes such work from durable effect evidence.

9. The detector does write `ANALYSIS_EXPIRED` for its own retry-limit/deadline path, so “it always ages out silently” is too broad. But a lane that is continuously non-idle is skipped before retry/outcome handling, and may leave the eligibility window with no detector terminal outcome. Retry state is also in memory.

10. Historical-only processing is behaviorally guarded but not structurally isolated: the same worker class contains both historical handling and an injected `PaperTradingService` used for live processing. This does not meet AGENTS.md’s stronger structural-isolation requirement.

11. Replay does not establish ingestion/recovery parity. The dataset forward path selects closed candles, but another replay helper does not; neither models provenance, close-transition tokens, reconciliation finality/grace, reconciliation audit, or direct-ingestion admission loss.

12. Production behavior is unknown. This review did not access production systems, deployed configuration, databases, logs, credentials, or runtime state.

## OBJECTIONS

- Current ordinary REST import can consume a live close without durable analysis admission or a recovery outcome.
- OBSERVE runs forbidden dual ingestion and can process imported STARTUP signals.
- Recovery is disabled by default and incomplete even when enabled.
- OFF-mode automatic resolution of interrupted processing is unproven; code explicitly parks it for review.
- Structural historical-only isolation, shared REST rate-limit/ban handling, crash/restart guarantees, and Replay parity are not demonstrated.
- AGENTS.md still calls V103 a fresh-install blocker, while B105 claims a trader-only baseline treatment. Neither document establishes an executed fresh-install proof.

Candidate for later solution review only: ordinary imports should not be allowed to finalise a runtime-open candle outside the same finality/grace, audit, and no-live-admission contract as reconciliation.
