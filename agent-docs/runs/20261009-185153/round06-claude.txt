# FINDINGS

## Corrections to my round-3 report

**1. Finding A: the defect is real, but its impact is a missing audit/outcome record and a Replay mismatch, not a lost trade.**
- Both Codex and I said a candle closed by the startup REST import becomes "ineligible for close dispatch". That is true, but under the intended design it was never dispatchable anyway.
  - A candle that closes while the trader is down is historical-only. The correct recovery path also never dispatches it: it records `SKIPPED_NOT_LIVE` (`LocalCandleReconciliationService.java:189`).
- What is actually wrong with the import path:
  - It closes the existing open row but leaves its provenance as `RUNTIME` with a NULL token (`CandleRepository.java:173-188`). A historical row is stored looking like a live one.
  - It writes no audit row and no terminal outcome, which breaks AGENTS.md's "one durable terminal outcome" rule.
  - Replay selects closed candles by time, so it will include this row even though production never analysed it.
- How often it happens is an inference: a 1m candle will be affected on most deploys, because the drain wait can be up to 120 s (`Deploy-Trader.ps1:112`). No measured downtime exists.

**2. My suggested fix for A was incomplete.**
- I suggested routing rows left open at shutdown through the update-only recovery path. That cannot work as things stand:
  - Recovery only looks at open rows (`closed=0`, `LocalCandleReconciliationService.java:131`).
  - It starts after a 15 s delay (`application.yml:45`).
  - The startup import (`@Order(10)` runner, `MarketDataBootstrapService.java:27,96`) has already closed those rows by then.
- So switching reconciliation on would change nothing for A. Any fix also needs the import to leave non-`BACKFILL` open rows alone.

**3. The comment contradiction is wider than one line.** Besides `CandleRepository.java:205`, two more comments contradict the code:
- `MarketDataBootstrapService.java:23-24` says only missing rows are inserted.
- `CandleRepository.java:127-130` says only recovery avoids stealing a live close.

## New findings this round

- **V103 changes the collector's schema, not just checks that it exists.**
  - It confirms the history database is `crypto_ai`, then adds indexes to `crypto_ai_v2.market_data_stream_event` (`V103...java:39-58`).
  - This is a startup migration rather than runtime access, so it isn't strictly the runtime rule AGENTS.md states. It still couples the trader to the collector's schema more tightly than "requires the table".

  - I believe baseline migrations may be limited to paid Flyway editions. If the edition in use doesn't support them, B105 is skipped without error, V103 runs, and a fresh install fails. This is unverified.

  - The key appears twice (`application.yml:40` and `:447`).

- **The bundled defaults auto-approve a LIVE cutover.**

  - Only the deploy script forces `activation-approved=false` (`Deploy-Trader.ps1:127`). A manual or IDE start with `SHARED_MARKET_MODE=LIVE` would inherit approval.

# OBJECTIONS (unresolved, material)
1. **The startup import and the manual/coin-activation import close open `RUNTIME` rows** with no audit row, no outcome and no provenance change. Switching reconciliation on does not fix this.
2. **OBSERVE in the main trader** runs direct ingestion, startup paper trading and collector consumption together, without any of the OFF-only safeguards. Nothing in the trader refuses OBSERVE.
3. **Reconciliation** is disabled, has no terminal age-out, and applies `LIMIT 50` before its due/evidence filtering.
4. **The detector keeps its retry state only in memory** with a short lookback, so after a longer outage some candles get no outcome.
5. **No shared Binance REST rate-limit or ban handling** across bootstrap, reconciliation and clock calls.
6. **Replay parity is not shown:** Replay selects by time, not by provenance or outcome.
7. **Fresh trader-only install is unproven.** V103 needs and alters `crypto_ai_v2`, and B105 may not be honoured by this Flyway edition.
8. **Duplicate `local-candle:` key** with no test that loads the configuration. Possible startup failure.
9. **Documentation drift:**
   - AGENTS.md calls the design "pending", but it is the code default.
   - claude-docs misdescribes OBSERVE and omits that backfill closes open rows.
   - Three source comments contradict the SQL they describe.
