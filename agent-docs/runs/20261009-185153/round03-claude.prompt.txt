**Corrections to my earlier findings:**
1. **I overstated OBSERVE mode.** It doesn't run collector execution alongside direct ingestion. In OBSERVE, the shared consumer reads the collector feed and inserts delivery rows. The real gap is narrower: after a crash or an outage longer than the lookback (180–600 s), its in-memory retry state is gone. Older closed-but-unanalysed candles are then never revisited and never get an outcome.
3. **The backfill race is now confirmed, not unknown.** Coin activation reloads the WebSocket first and then runs the backfill, so the two overlap. The manual `POST /api/market-data/import` endpoint can run the same backfill against a live symbol at any time.
