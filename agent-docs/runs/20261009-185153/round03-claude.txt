**Where the two reviews agree, confirmed in code:**
- **OFF mode (the checked-in default):** the trader owns everything for candles.
  - It runs the Binance WebSocket itself (`BinanceWebSocketManager.java:28,97`).
  - It runs the REST bootstrap and import (`MarketDataService.java:31-56`).

- **Closing a candle:** an update can never reopen a closed row (`closed=GREATEST(...)`). A close-transition token is created only when a row goes from open to closed (`CandleRepository.java:201`), and only the write that owns that token sends the candle for analysis (`:120`).
- **LIVE mode:** the collector owns candle writes (`requireLocalWriter`, `:54-56`). Direct ingestion, import and bootstrap all refuse to run or do nothing.
- **Recovery:** the code exists but is switched off (`application.yml:44`). Recovery paths only insert missing candles or only update open ones, and record `SKIPPED_NOT_LIVE` rather than a close token (`LocalCandleReconciliationService.java:183-189`).

# EVIDENCE

- **Backfill closes open rows without a token:**
  - `CandleRepository.java:173-188`: the backfill's insert-or-update sets `closed=GREATEST(...)` with no token clause, and leaves `ingestion_source` unchanged.
  - Once that happens, three things fail:
    - the WebSocket's own close no longer wins the token (`:120`)
    - the detector needs a non-null token (`LocalClosedCandleDetector.java:50`)
    - reconciliation needs `closed=0` (`LocalCandleReconciliationService.java:131`)
  - Result: no analysis and no terminal outcome for that candle.
  - Two code comments say the opposite: `CandleRepository.java:205` ("backfill inserts missing identities only") and line 175.
- **Duplicate top-level key:** `application.yml:40` and `:447` both start a `local-candle:` block.
- **Recovery audit never gives up:**
  - `LocalReconciliationAuditRepository.due` (`:35-38`) keeps `PENDING` rows due forever.
  - `pending()` (`LocalCandleReconciliationService.java:194-196`) caps the backoff at 300 s but has no attempt limit.
  - Candidates are limited to the active window (`:125-126, 147-149`). Once a candle leaves it, the row stays `PENDING` with no `candle_analysis_outcome` (outcomes are only written at `:189, :211`).
  - The open-candidate query takes `LIMIT 50` *before* filtering by `due`/loss evidence (`:133, 139-140`), so old rows that aren't due can crowd out newer ones.
- **Detector:** retry state is held in memory (`:28-29`). It writes `ANALYSIS_EXPIRED` when it gives up (`:99-104, 113-118, 140-141`). The lookback is at least 180 s (`:47`).
- **No rate-limit handling:** searching `src/main/java` for `429`, `418`, `Retry-After`, `RateLimit` and `X-MBX-USED-WEIGHT` finds nothing.
- **V103 / B105:**

# OBJECTIONS

1. **Duplicate `local-candle:` key.** Startup may fail, or one block may silently override the other. Not tested.
2. **The backfill can close an open row with no token** (import endpoint, or coin activation after the WebSocket reload). That candle is left with no analysis and no durable outcome. This breaks AGENTS.md's "one durable terminal outcome" rule, and the code comments misdescribe it.
3. **Automatic recovery is switched off by default.** AGENTS.md requires automatic recovery with no manual step.
4. **Reconciliation can leave rows `PENDING` forever** once they leave the window, with no terminal outcome. This breaks the "age out to a durable explicit outcome" rule.
5. **The detector loses its state on a crash.** After an outage longer than its 180–600 s lookback, candles get no outcome.
6. **No shared Binance REST rate-limit or ban handling** (required by AGENTS.md).
7. **OBSERVE** connects to the collector and runs the shared executors alongside direct ingestion. Its direct ingestion also runs without any of the OFF-only safeguards. Nothing stops anyone selecting it.
8. **Fresh Replay doesn't match production on which candles get analysed** (backfilled, `SKIPPED_NOT_LIVE` and token-less candles).
9. **Trader-only bootstrap through B105 is unproven** on MySQL with this Flyway edition.
10. **Documentation is stale.** AGENTS.md calls the local-candle design not implemented, but it's the working-tree default. claude-docs say nothing automatically repairs a missed close and present V103 as the only bootstrap blocker without mentioning B105.
