## New findings

**A. Every restart leaves candles with no analysis outcome.**
- The startup bootstrap runs before the WebSocket starts:
  - bootstrap is an `ApplicationRunner` with `@Order(10)` (`MarketDataBootstrapService.java:26-30`)
  - the WebSocket starts on `ApplicationReadyEvent` (`BinanceWebSocketManager.java:95`)
- Historical bootstrap is on (`application.yml:85`) and imports at least 300 candles (`MarketDataBootstrapService.java:37,59-62`).
- So any candle row still open at shutdown, whose close time has since passed, gets closed by `upsert` (`BACKFILL` duplicate clause). The result is:
  - no token
  - provenance left as `RUNTIME`
  - no `candle_analysis_outcome`
- This also beats reconciliation to it: reconciliation starts 15 s later (`application.yml:45`) and would otherwise have recorded `SKIPPED_NOT_LIVE`.
- No live trade is lost, because the candle is stale either way. But it breaks AGENTS.md's "one durable terminal outcome" rule on every restart. The file's own comment (line 23: "only missing Binance rows are inserted") and `CandleRepository.java:205` both say the opposite.

**B. In OBSERVE, the bootstrap generates and processes signals.**
- The analysis guard only checks `"OFF".equals(marketMode)` (`MarketDataBootstrapService.java:107`).
- In OBSERVE, after the REST import the bootstrap runs `calculateAndPersist`, then `analyzeForProcessing(..., STARTUP)`, then `paperTradingService.processSignal(signal)` (`:111-136`). The same happens when a coin is activated (`bootstrapSymbol`).
- That is a REST-backfill-to-paper-trading path in a mode that also runs the collector consumer.
- I did not trace whether downstream freshness gates reject a STARTUP signal.

**C. The duplicate `local-candle:` key (`application.yml:40` and `:447`) is probably a startup failure.**
- As far as I know, Spring Boot's YAML loader rejects duplicate keys rather than merging them. I have not checked that against Boot 4.1.0, and nothing was run.
- No `@SpringBootTest` exists anywhere in `src`, so no test would catch it.

**D. More detail on reconciliation.**
- `PENDING` rows have no attempt limit and never age out (`LocalReconciliationAuditRepository.java:35-38`, `LocalCandleReconciliationService.java:194-196`).
- Candidates are taken `LIMIT 50` per interval, oldest first, before filtering by `due` and loss evidence (`:133`, `:139-140`). Open rows that aren't due or have no loss evidence can keep filling that limit.
- Codex didn't raise the never-ending `PENDING` rows; my previous objection stands.

**E. More documentation contradictions.**
- `claude-docs/ARCHITECTURE.md:45-47` says `SharedAnalysisDispatcher` drives analysis in LIVE/OBSERVE. That is wrong for OBSERVE: deliveries are marked `OBSERVED` and return (`SharedMarketConsumer.java:480`).
- `:77-81` says backfill never sets a token, which is true, but leaves out that it closes open rows.
- `:92-95` leaves out the manual import endpoint.
- `:97` ("Nothing repairs this automatically") is stale; `codex-docs/ARCHITECTURE.md:137` acknowledges the reconciliation code.

# OBJECTIONS (unresolved)
1. **Probable startup failure** from the duplicate YAML key, with no test that loads the configuration.
2. **Backfill closes open rows with no token or outcome.** It happens deterministically on every restart, can also hit a live close during coin activation or a manual `POST /import`, and the code comments say the opposite.
3. **OBSERVE turns backfill into STARTUP signals that reach paper-trading processing,** and it also runs the collector consumer alongside direct ingestion. Nothing stops anyone selecting it.
4. **Reconciliation is off by default,** has no terminal outcome for rows that leave the window, and can be crowded out by the `LIMIT 50`.
5. **The detector keeps its retry state only in memory,** so after an outage longer than its 180–600 s lookback, candles get no outcome.
6. **No shared Binance REST rate-limit or ban handling.**
7. **Replay analyses candles that production never would** (backfilled, `SKIPPED_NOT_LIVE` or token-less), so parity is not shown.
8. **Trader-only install via B105 is unproven,** and V103 still needs `crypto_ai_v2`.
9. **Documentation is stale** in AGENTS.md (which calls local-candle pending although it is the default in the working tree), in claude-docs (finding E) and in my own previous report.
