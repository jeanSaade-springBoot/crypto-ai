- All six frozen `paper_position` records remain in scope. The archived production logs for 2026-10-12 are present and cover their lifecycle times.

- Every close has a nearby accepted (`APPLIED`) price observation, but log proximity alone does not prove that event caused the close. Nearest logged observation versus persisted close:

- Position 182 has the strongest timing alignment: accepted price event `2007194` observed at `10:05:20.431 UTC`, followed by persisted close at `10:05:20.486 UTC`. This is consistent with a fast price-driven decision, but requires the durable exit-audit/wallet linkage to establish causation.

- Position 158’s contemporaneous 1m `STRONG_SELL` and 5m `SELL` signals were saved at `03:30:02.807 UTC` and `03:30:02.816 UTC`; the position closed at `03:30:06.638 UTC` with `SELL_CONFIRMED`. This is temporally consistent with a signal/policy exit, but the close label is not enough to identify the actual exit signal.

- Positions 162 and 182 closed before the newly produced signals in their respective close-minute pipelines were saved:
  - 162 closed at `04:26:04.116 UTC`; the shown 1m signal was saved at `04:26:04.275 UTC`, with `NEUTRAL`.
  - 182 closed at `10:05:20.486 UTC`; its shown 1m/5m signals were saved around `10:05:30.288 UTC`, both `WATCH`.

  Therefore those particular new signals cannot have caused those closes. A prior signal, live price protection, or another recorded path must be examined.

- Position 172 closed as `HTF_SELL_CONFIRMED` at `07:15:45.484 UTC`, while the close-minute 1m/5m signals were `NEUTRAL` and `WATCH`. This is compatible with use of prior 1h evidence, but is not proof without `exit_signal_id` and the audit record.

- Current source supports durable audit evidence through `production_exit_audit`, wallet execution timestamps, `trade_signal` timestamps, and `market_price_event` outcome records. The current source must not be treated as the exact deployed version on 2026-10-12 without deployment/version evidence.

### AGENT INFERENCE

- No timing defect is confirmed. The observed close-to-price intervals range from 55 ms to roughly 6 seconds and do not, by themselves, prove an unacceptable delay.
- The primary forensic gap is lineage, not lack of nearby market activity: the available logs do not directly state `paper_position.id`, exit-signal ID, wallet execution ID, and price-event ID in one record.

```sql
SELECT
    p.id AS paper_position_id,
    p.symbol,
    p.status,
    p.signal_id AS entry_signal_id,
    p.exit_signal_id,
    p.close_reason,

    xs.candle_open_time AS exit_candle_open_utc,
    xs.generated_at AS exit_generated_utc,
    xs.created_at AS exit_row_created_utc,
    xs.latest_price AS exit_signal_price,
    xs.data_quality_valid AS exit_data_quality_valid,
    xs.explanation AS exit_signal_explanation,
    a.id AS exit_audit_id,
    a.close_trigger AS audit_close_trigger,
    a.source_signal_id AS audit_source_signal_id,
    a.source_signal_decision AS audit_source_signal_decision,
    a.exit_price_usdt AS audit_exit_price,
    a.close_explanation AS audit_close_explanation,
    a.audited_at AS audit_created_utc
FROM paper_position p
LEFT JOIN trade_signal es ON es.id = p.signal_id
LEFT JOIN trade_signal xs ON xs.id = p.exit_signal_id
LEFT JOIN production_exit_audit a ON a.paper_position_id = p.id
WHERE p.id IN (182, 172, 162, 158, 143, 137)
ORDER BY FIELD(p.id, 182, 172, 162, 158, 143, 137);
```

### DB_REQUEST

QueryId: DBQ-CODEX-I3-002  
Purpose: Obtain bounded wallet and accepted-price timing evidence nearest each frozen close, including event IDs needed to reconcile the archived logs.  
SQL:

```sql
WITH frozen AS (
    SELECT id, symbol, signal_id, exit_signal_id, opened_at, closed_at
    FROM paper_position
    WHERE id IN (182, 172, 162, 158, 143, 137)
),
near_price AS (
    SELECT
        f.id AS paper_position_id,
        e.id AS market_price_event_id,
        e.symbol,
        e.observed_at,
        e.price,
        e.source,
        e.delivery_status,
        e.outcome_reason,
        ROW_NUMBER() OVER (
            PARTITION BY f.id
            ORDER BY ABS(TIMESTAMPDIFF(MICROSECOND, e.observed_at, f.closed_at)), e.id
        ) AS proximity_rank
    FROM frozen f
    JOIN market_price_event e
      ON e.symbol = f.symbol
     AND e.observed_at BETWEEN f.closed_at - INTERVAL 90 SECOND
                           AND f.closed_at + INTERVAL 90 SECOND
)
SELECT
    'PRICE_EVENT' AS evidence_type,
    paper_position_id,
    market_price_event_id AS evidence_id,
    symbol,
    observed_at AS evidence_time_utc,
    price,
    source,
    delivery_status,
    outcome_reason,
    proximity_rank
FROM near_price
WHERE proximity_rank <= 6
ORDER BY paper_position_id, proximity_rank;

SELECT
    f.id AS paper_position_id,
    wt.id AS wallet_trade_id,
    wt.symbol,
    wt.side,
    wt.status,
    wt.execution_type,
    wt.execution_reason,
    wt.price_usdt,
    wt.decision_price_usdt,
    wt.execution_price_observed_at,
    wt.executed_at,
    wt.realized_pnl_usdt,
    wt.fee_usdt,
    wt.execution_message
FROM frozen f
JOIN wallet_trade wt
  ON wt.symbol = f.symbol
 AND (
        wt.signal_id IN (f.signal_id, f.exit_signal_id)
        OR wt.executed_at BETWEEN f.opened_at - INTERVAL 5 SECOND
                              AND f.closed_at + INTERVAL 5 SECOND
     )
ORDER BY f.id, wt.executed_at;
```
