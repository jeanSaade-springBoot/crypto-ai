- **PROJECT EVIDENCE:** Direct-price exit precedence is: take-profit handling, absolute stop loss, protected-profit hard floor, profit-lock decision, then confirmed normal multi-timeframe exit. The normal policy permits `HTF_SELL_CONFIRMED` or `SELL_CONFIRMED`; profit-lock has its own outcomes.
- **PROJECT EVIDENCE:** A live mechanical exit closes the wallet first; only a successful `executeMechanicalExit(...)` permits `closePaper(...)`. The close records terminal price, cumulative realized P&L, status, close reason, explanatory text, UTC close time, and immutable exit audit.
- **PROJECT EVIDENCE:** `closePaper(...)` does not set `paper_position.exit_signal_id`. Therefore, a null exit-signal link is compatible with a valid direct-price TP/SL/profit-lock/signal-policy closure. Its evidence route is `production_exit_audit` plus related `market_price_event` and `wallet_trade`, not an inferred missing signal.
- **PROJECT EVIDENCE:** Signal-path closes do set `exit_signal_id`; they can result from TP, SL, profit lock, or validated SELL/STRONG_SELL processing. This route uses the signal as context and records the actual terminal reason in wallet/audit data.
