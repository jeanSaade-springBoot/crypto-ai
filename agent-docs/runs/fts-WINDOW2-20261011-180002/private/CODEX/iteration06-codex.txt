## FINDINGS

- **[PROJECT EVIDENCE]** No executed result exists in the permitted `db/CODEX` folder. Therefore none of the six frozen losses—`104, 101, 96, 91, 82, 78`—can yet be assigned a trade-specific root cause.

- **[PROJECT EVIDENCE — trade 104 candidate]** The logs previously identified a live EDUUSDT profit-lock breach at UTC `2026-10-10 14:45:22.035` / KSA `17:45:22.035`, held by the live route under `1h=BUY, 5m=WATCH, 1m=WATCH`. A 1m signal route then logged a profit-lock trigger at UTC `14:46:01.312` / KSA `17:46:01.312`. The observed interval is ~39.3 seconds.

- **[PROJECT EVIDENCE]** The two paths have materially different rules:
  - Live protection calls `PositionExitPolicy`; it holds a breached profit lock with bullish 1h plus supportive 5m. [LivePositionProtectionService.java](/C:/workspace/crypto-ai-trader-mysql/src/main/java/com/crypto/position/service/LivePositionProtectionService.java:219) [PositionExitPolicy.java](/C:/workspace/crypto-ai-trader-mysql/src/main/java/com/crypto/position/service/PositionExitPolicy.java:57)
  - Signal processing closes immediately when its own profit-lock evaluation is triggered; it does not call that policy. [PaperTradingService.java](/C:/workspace/crypto-ai-trader-mysql/src/main/java/com/crypto/service/PaperTradingService.java:176)

- **[AGENT INFERENCE — trade 104]** This is a credible exit-route divergence candidate, not yet a confirmed cause of position `104`’s loss. The database must prove that these log events map to `paper_position.id=104`, identify the wallet position and audit trigger, and reconcile any partial realization.

- **[PROJECT EVIDENCE]** There is also a confirmed consistency risk in the signal exit route: it persists the paper close before attempting the wallet exit, then catches a wallet exception. [PaperTradingService.java](/C:/workspace/crypto-ai-trader-mysql/src/main/java/com/crypto/service/PaperTradingService.java:501) [PaperTradingService.java](/C:/workspace/crypto-ai-trader-mysql/src/main/java/com/crypto/service/PaperTradingService.java:515) The live route performs the wallet mechanical exit first and closes paper state only on success. [LivePositionProtectionService.java](/C:/workspace/crypto-ai-trader-mysql/src/main/java/com/crypto/position/service/LivePositionProtectionService.java:165) This is not evidence that it occurred in any frozen trade.

- **[PROJECT EVIDENCE]** Paper P&L retains any earlier realized component when the remainder is closed. Thus, a final exit price above the initial paper entry does not alone disprove a negative final `realized_pnl`; partial-harvest and wallet records are required. [PaperTradingService.java](/C:/workspace/crypto-ai-trader-mysql/src/main/java/com/crypto/service/PaperTradingService.java:457)

- **[EXTERNAL RESEARCH]** OHLC candles cannot establish the order of intrabar stop/target/lock contacts; price-event ordering is needed. This reinforces the project rule not to use candle high/low as a substitute for accepted protection evidence. [Research summary](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=6240638)

### DB_REQUEST
QueryId: DBQ-CODEX-I6-001  
Purpose: Establish the bounded, durable root-cause chain for exactly the six frozen positions: authoritative lifecycle, immutable exit audit, managed position, related signals, wallet fills, and accepted/rejected price evidence around each close. Raw timestamps must be interpreted as UTC; KSA is UTC+03:00.

SQL:
```sql
SELECT
    @@session.time_zone AS session_time_zone,
    @@global.time_zone AS global_time_zone,
    @@system_time_zone AS system_time_zone;

SELECT
    table_name,
    ordinal_position,
    column_name,
    column_type,
    is_nullable,
    column_key
FROM information_schema.columns
WHERE table_schema = 'crypto_ai'
  AND table_name IN (
      'paper_position',
      'production_exit_audit',
      'wallet_managed_position',
      'wallet_trade',
      'trade_signal',
      'market_price_event'
  )
ORDER BY table_name, ordinal_position;

SELECT
    p.*,
    pea.id AS exit_audit_id,
    pea.wallet_position_id,
    pea.close_trigger AS audit_close_trigger,
    pea.source_signal_id AS audit_source_signal_id,
    pea.source_signal_decision AS audit_source_signal_decision,
    pea.entry_price_usdt AS audit_entry_price_usdt,
    pea.exit_price_usdt AS audit_exit_price_usdt,
    pea.close_explanation AS audit_close_explanation,
    pea.audited_at
FROM crypto_ai.paper_position p
LEFT JOIN crypto_ai.production_exit_audit pea
  ON pea.paper_position_id = p.id
WHERE p.id IN (104, 101, 96, 91, 82, 78)
ORDER BY FIELD(p.id, 104, 101, 96, 91, 82, 78);

SELECT wmp.*
FROM crypto_ai.wallet_managed_position wmp
JOIN crypto_ai.production_exit_audit pea
  ON pea.wallet_position_id = wmp.id
WHERE pea.paper_position_id IN (104, 101, 96, 91, 82, 78)
ORDER BY pea.paper_position_id, wmp.id;

SELECT ts.*
FROM crypto_ai.trade_signal ts
WHERE ts.id IN (
    SELECT signal_id
    FROM crypto_ai.paper_position
    WHERE id IN (104, 101, 96, 91, 82, 78)
    UNION
    SELECT exit_signal_id
    FROM crypto_ai.paper_position
    WHERE id IN (104, 101, 96, 91, 82, 78)
    UNION
    SELECT source_signal_id
    FROM crypto_ai.production_exit_audit
    WHERE paper_position_id IN (104, 101, 96, 91, 82, 78)
)
ORDER BY ts.generated_at, ts.id;

SELECT
    p.id AS paper_position_id,
    wt.*
FROM crypto_ai.paper_position p
JOIN crypto_ai.wallet_trade wt
  ON wt.symbol = p.symbol
 AND wt.executed_at >= p.opened_at - INTERVAL 1 MINUTE
 AND wt.executed_at <= p.closed_at + INTERVAL 1 MINUTE
WHERE p.id IN (104, 101, 96, 91, 82, 78)
ORDER BY p.id, wt.executed_at, wt.id;

SELECT
    p.id AS paper_position_id,
    mpe.*
FROM crypto_ai.paper_position p
JOIN crypto_ai.market_price_event mpe
  ON mpe.symbol = p.symbol
 AND mpe.observed_at >= p.closed_at - INTERVAL 2 MINUTE
 AND mpe.observed_at <= p.closed_at + INTERVAL 15 SECOND
WHERE p.id IN (104, 101, 96, 91, 82, 78)
ORDER BY p.id, mpe.observed_at, mpe.id;
```
