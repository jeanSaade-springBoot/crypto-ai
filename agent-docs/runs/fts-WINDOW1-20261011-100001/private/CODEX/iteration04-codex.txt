- **PROJECT EVIDENCE:** Live executable flow is:

- **PROJECT EVIDENCE:** A normal stop-loss close is written with status `STOPPED`; the frozen selection requires `status=CLOSED`. Therefore, assuming the supplied selection is correct, this study excludes ordinary stop-loss-position records and focuses on other terminal-close routes (for example confirmed SELL, profit-lock, TP, manual, or higher-timeframe exits).

- **PROJECT EVIDENCE:** Direct price protection has priority over signal-based exits: take-profit handling, stop-loss, profit-lock protection, then confirmed multi-timeframe exits, then near-TP partial harvest. Accepted direct observations must be fresh, ordered, and durably marked `APPLIED`.

- **PROJECT EVIDENCE:** Signal-route exits use a signal price only when its candle observation is not before the position opening time. Automatic processing also rejects a candle that is no longer latest/fresh; the 1m processing grace is 90 seconds.

- **AGENT INFERENCE:** Each frozen loss requires wallet-ledger and exit-audit corroboration. In the signal-close path, `paper_position` is closed before `executeSignalLinkedExit(...)` is invoked; that wallet method has no success return and may return without an effect when no open managed position, no quantity, or an idempotent prior sell exists. This is not evidence that any frozen trade is inconsistent, but it makes wallet-trade, managed-position, and exit-audit records mandatory before treating a paper loss as a confirmed executed loss.
