## FINDINGS

- **PROJECT EVIDENCE:** Frozen scope remains exactly `paper_position` IDs `104, 101, 96, 91, 82, 78`.
- **PROJECT EVIDENCE:** `logs/crypto-ai-trader.log` covers `2026-10-11 06:35:04–07:00:03 UTC` (KSA `09:35:04–10:00:03`) within the study cutoff. It contains no explicit frozen position/trade ID match, so no log event can be attributed to any selected loss.
- **PROJECT EVIDENCE:** The runtime repeatedly logged an exchange clock ahead of database/JVM by `3,106–3,145 ms` during `06:35–06:59 UTC` (KSA `09:35–09:59`). Automatic corrections were reported active.
- **PROJECT EVIDENCE:** Pre-snapshot log metrics include 463 negative `liveCloseToGenerationMs` and 359 negative `liveCloseToInsertionMs`. This is consistent with an exchange-time-confirmed close being processed while raw JVM/database time remains about three seconds behind exchange time.
- **AGENT INFERENCE:** These negative metrics are not evidence of early use of an unclosed Binance candle, nor evidence of latency, unless the persisted candle close and exchange-clock-corrected admission evidence for a specific selected trade contradict them.
- **PROJECT EVIDENCE:** The same log interval records no `ERROR`, no `outcome=FAILED`, and no nonzero runtime summary values for input/pipeline/protection “failed or unconfirmed” counters. This is only system-level evidence; it neither proves nor disproves correct execution for the six closed losses.
- **PROJECT EVIDENCE:** One 615 ms symbol-lock wait was logged for unrelated `AEROUSDT` activity. The log identifies no frozen position ID, so it must not be associated with a selected loss.
- **PROJECT EVIDENCE:** Snapshot metadata remains internally inconsistent: `2026-10-11 07:00:03 UTC` converts to `2026-10-11 10:00:03 KSA`, not the stated `10:00:01 KSA`. The intended clock is `10:00:00 KSA`.
