## FINDINGS

**F-I1-01: The charter's snapshot clock is internally inconsistent.** [PROJECT EVIDENCE + AGENT INFERENCE]
- CHARTER.md lines 4–5 give `SNAPSHOT TIME UTC: 2026-10-25 10:08:57` and `SNAPSHOT TIME KSA: 2026-10-23 11:36:38`.
- UTC+3 of the stated UTC time is **2026-10-25 13:08:57 KSA**, not 2026-10-23 11:36:38.
- The KSA value matches the run ID `fts-WINDOW1-20261023-113638`. That KSA time is UTC **2026-10-23 08:36:38**.
- The two labels are about 2 days apart, so at least one label is wrong. The study selected "latest 6 losing trades" (`ORDER BY closed_at DESC LIMIT 6`), so which instant is correct decides whether the frozen set is really the latest six at the snapshot.
- I am not substituting trades. I treat 182, 172, 162, 158, 143 and 137 as the mandatory set and ask for a check that they match the selection at either instant (DBQ-CLAUDE-I1-002).

**F-I1-02: Planned reconstruction method for each trade.** [PROJECT EVIDENCE: claude-docs/TRADE_INVESTIGATION_AGENT.md, claude-docs/TRADING_RULES.md]
- For each trade I will rebuild this chain: candle close → `trade_signal` saved → `signal_processing_work` claimed → entry (`paper_position.opened_at` / `wallet_trade` BUY) → `market_price_event` observations → exit trigger (`production_exit_audit.close_trigger`) → exit committed (`closed_at` / `wallet_trade` SELL).
- I will show both UTC and KSA and measure the latency of each step.
- Things to keep in mind when reading the results:
  - **P&L is gross:** automatic trades record `fee_usdt = 0` (INVESTIGATION_LOG item 2), so fees must be calculated separately.
  - **Stop-loss can move:** `paper_position.stop_loss` is the final value, and the stop only moves up. Trade 182 may have been stopped at a raised stop, which is not the same as being stopped at the original stop.
  - **Paper can close without the wallet:** `PaperTradingService.completeClose` still closes the paper position if the wallet exit fails. I will check that the paper and wallet records agree.
  - **Price evidence:** only `LEGACY` and `APPLIED` price events count as accepted. I will not use candle OHLC to fill gaps.

**F-I1-03: Schema version is unknown, so some columns may not exist.** [PROJECT EVIDENCE: V106/V107]
- `trade_signal.signal_mode` comes from V106, and `trade_signal.data_quality_valid` plus `buy_htf_assessment_audit` come from V107.
- AGENTS.md says FIX-154 (V107) is not implemented. I can't assume the snapshot database has V106 or V107, so queries that use those columns are kept separate (DBQ-CLAUDE-I1-004B and I1-012) so a missing column doesn't break the main queries.

### DB_REQUEST

Purpose: Get the actual schema of the tables involved, and the latest applied migrations (U-03, U-04).

SELECT table_name, ordinal_position, column_name, column_type
FROM information_schema.columns

### DB_REQUEST
QueryId: DBQ-CLAUDE-I1-004
Purpose: Get the entry and exit signals, including decision chain, regime, strategy, multi-timeframe and BTC context, and risk/reward. Large JSON columns are left out.

SELECT pp.id AS pp_id, CASE WHEN ts.id = pp.signal_id THEN 'ENTRY' ELSE 'EXIT' END AS role,

       ts.decision, ts.original_decision, ts.total_score, ts.confidence_score, ts.final_entry_allowed,
       ts.latest_price, ts.stop_loss, ts.take_profit, ts.risk_reward_ratio, ts.atr_at_signal, ts.atr_percent,
       ts.atr_entry_type, ts.atr_recommended_position_percent, ts.atr_overextended,
       ts.market_regime, ts.market_regime_confidence, ts.selected_strategy, ts.strategy_entry_allowed,

### DB_REQUEST
QueryId: DBQ-CLAUDE-I1-006
Purpose: Get the wallet executions in each trade's lifetime, to recompute P&L and check paper vs wallet (F-I1-02).

SELECT pp.id AS pp_id, wt.id, wt.signal_id, wt.execution_key, wt.side, wt.quantity, wt.price_usdt,

### DB_REQUEST
QueryId: DBQ-CLAUDE-I1-009
Purpose: Get price-event coverage over each trade's lifetime: counts by delivery status, min/max price, and the first moment price was at/below the final stop or at/above the target.
SQL:
SELECT pp.id AS pp_id, pp.symbol, m.delivery_status, COUNT(*) AS n, MIN(m.price) AS min_px, MAX(m.price) AS max_px,
       MIN(m.observed_at) AS first_obs, MAX(m.observed_at) AS last_obs,
       MIN(CASE WHEN m.price <= pp.stop_loss THEN m.observed_at END) AS first_le_final_sl,
       MIN(CASE WHEN m.price >= pp.take_profit THEN m.observed_at END) AS first_ge_final_tp
FROM paper_position pp
JOIN market_price_event m ON m.symbol = pp.symbol
 AND m.observed_at BETWEEN pp.opened_at AND pp.closed_at + INTERVAL 5 SECOND
WHERE pp.id IN (182,172,162,158,143,137)
GROUP BY pp.id, pp.symbol, m.delivery_status ORDER BY pp.id DESC, m.delivery_status;
### END_DB_REQUEST

### DB_REQUEST
QueryId: DBQ-CLAUDE-I1-010
Purpose: Find the largest gap between price observations during each trade, to detect protection blind spots.
SQL:
SELECT pp_id, COUNT(*) AS n, MAX(gap_s) AS max_gap_s, SUM(gap_s > 10) AS gaps_over_10s
FROM (
  SELECT pp.id AS pp_id,
         TIMESTAMPDIFF(SECOND, LAG(m.observed_at) OVER (PARTITION BY pp.id ORDER BY m.observed_at, m.id), m.observed_at) AS gap_s
  FROM paper_position pp
  JOIN market_price_event m ON m.symbol = pp.symbol
   AND m.observed_at BETWEEN pp.opened_at AND pp.closed_at
  WHERE pp.id IN (182,172,162,158,143,137)
) t GROUP BY pp_id ORDER BY pp_id DESC;
### END_DB_REQUEST

### DB_REQUEST
QueryId: DBQ-CLAUDE-I1-011
Purpose: Get the price events right around entry and exit, to check fill price against the latest price and the exit trigger tick.
SQL:
SELECT pp.id AS pp_id, CASE WHEN m.observed_at <= pp.opened_at + INTERVAL 2 SECOND
                             AND m.observed_at >= pp.opened_at - INTERVAL 20 SECOND THEN 'ENTRY' ELSE 'EXIT' END AS edge,
       m.id, m.observed_at, m.price, m.source, m.delivery_status, m.created_at
FROM paper_position pp
JOIN market_price_event m ON m.symbol = pp.symbol
 AND (m.observed_at BETWEEN pp.opened_at - INTERVAL 20 SECOND AND pp.opened_at + INTERVAL 2 SECOND
   OR m.observed_at BETWEEN pp.closed_at - INTERVAL 20 SECOND AND pp.closed_at + INTERVAL 2 SECOND)
WHERE pp.id IN (182,172,162,158,143,137)
ORDER BY pp.id DESC, m.observed_at, m.id LIMIT 300;
### END_DB_REQUEST

### DB_REQUEST
QueryId: DBQ-CLAUDE-I1-012
Purpose: Get the 1m and 5m candles that were available at entry (gaps, closed flag, provenance), plus FIX-154 audit rows if that table exists.
SQL:

WHERE pp.id IN (182,172,162,158,143,137) ORDER BY a.reference_signal_id, a.evaluated_at LIMIT 60;
