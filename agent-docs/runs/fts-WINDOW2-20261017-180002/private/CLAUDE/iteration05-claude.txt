## FINDINGS

### F5-1 [PE code + DB]: the 0.5% stop floor plus a 3× ATR target makes R:R collapse when ATR is low

**Code** (`AtrRiskService.java:34-45`, `application.yml:137-143`):
- Stop = max(2×ATR, 0.50% of price).
- Target = 3×ATR. Nothing scales the target up when the stop is floored.
- So once ATR is below 0.25% of price, R:R = 6 × ATR%, and it falls below 1 whenever ATR is under 0.167% of price.

**Per trade** (the geometry is recomputed at the fill price):

| ID | Implied 1m ATR % | Stop distance | Target distance | R:R (signal / at fill) | Stop floored? |
|---|---|---|---|---|---|
| 137 | 0.107% | 0.500% | 0.322% | 0.64 / 0.64 | yes |
| 143 | 0.27% | 0.54% (0.565% at fill) | 0.81% (0.786% at fill) | 1.50 / 1.39 | no |
| 158 | 0.055% | 0.50% (0.493% at fill) | 0.17% | 0.33 / 0.35 | yes |
| 162 | 0.073% | 0.500% | 0.219% | 0.44 / 0.44 | yes |
| 172 | 0.124% (**0.68 of one price tick**) | 0.500% | 0.372% | 0.74 / 0.74 | yes |
| 182 | 0.080% (about 1.5 ticks) | 0.500% | 0.241% | 0.48 / 0.48 | yes |

- The volatility level is LOW for all six (ATR under 0.50% of price). That `volatilityLevel` field is display-only: its only reads are in `DashboardApiController:1205,1313`, so it never gates a trade.
- The 5m authorities were floored too. 159285 has R:R 1.37 and 165415 has R:R 0.80.

### F5-2 [PE code]: R:R and fees never block an entry

- **No hard R:R gate exists.** The signal's `risk_reward_ratio` is only read for display (`DashboardApiController`, `TradeInspectorService`).
- Inside Execution Intelligence (EI), R:R is used in only two places:
  - The EQ score: −30 when R:R < 1, −15 when R:R < 1.25 (`ExecutionIntelligenceService.java:991-993`).
  - The scout route, which needs R:R ≥ 1.25 (`:1055`).
- **EQ is a size cap, not a veto,** unless the score is below 50 (`:1171-1183`, `CHASE_ENTRY_CUTOFF=50` at `:229`). An entry with R:R 0.33 can score up to 70, which is GOOD_ENTRY.
- **Fees are not modelled.** Searching `src/main` for any fee-rate configuration finds nothing, and `fee_usdt=0` on all 13 fills (I1-004).
- **[ER]** Binance spot charges regular users 0.10% maker and 0.10% taker (0.075% when paid in BNB). That is about 0.20% for a round trip. The sources are third-party guides, not Binance's own fee page.

**[AI] Break-even win rate per trade:**

|---|---|---|
| 137 | 60.8% | 85.2% |
| 143 | 41.8% | 56.6% |
| 158 | 74.2% | **impossible** (the target nets −0.03% after fees) |
| 162 | 69.5% | 97.4% |
| 172 | 57.3% | 80.3% |
| 182 | 67.5% | 94.5% |

- Four of the six (158, 162, 172, 182) would have had a sharply negative expected value in live trading, whatever the signal quality. 137 also needs an 85% win rate after fees.

### F5-4 [PE code + DB]: the EQ that admits an entry and the EQ that gets persisted use different ATRs

**The two calculations:**
- **Admission:** the SETUP_TIMEFRAME_ATR route scores EQ with the 5m ATR (`:631-635`) and the wake-up route does the same (`:439`). The code comment says this avoids "a tiny 1m ATR" that would falsely flag a chase.
- **Fill:** the execution-time recheck (`:1167`) and the persisted score (`PaperTradingService:378`) use the 1m ATR.

**143 inverts the comment's assumption:**
- The 1m ATR was 0.0109. It was inflated by the 22:39 candle, whose range ran from 3.990 to 4.053.
- The 5m ATR from 159285 was 0.00907, which is *smaller*.
- That explains both numbers: the message's EQ of 60 used the 5m ATR [PRIOR-RUN PE excerpt], and the persisted 70 used the 1m ATR. Both are consistent with the reference price in F5-3.

**Effect:** no decision changed for the six, since both scores were above 50 and the size cap was 25% either way. But the persisted EQ is **not the value that admitted the trade**. That is a forensic and Replay-diagnostic gap.

### F5-5 [PE code + DB]: 162 was admitted as BALANCED_EARLY at a price the system rated LATE_ENTRY

- **The entry:** EI route ACCUMULATED_EVIDENCE, FIX-154 result BALANCED_EARLY (audit 2199: 5m WATCH 122 s old, 1h WATCH 122 s old), EQ 50 LATE_ENTRY (wallet trade 403).
- **FIX-041 doesn't apply here:** it blocks BALANCED_EARLY combined with LATE_ENTRY, but only on the IMMEDIATE_VALIDATION route (`:672-684`). Its comment explicitly leaves accumulated evidence outside that check.
- **FIX-119 doesn't apply either:** its late-entry deferral (`:1275-1280`) is skipped when there is even one BUY among the observations. 162 had 1 BUY and 9 WATCH.
- **Price action:** the entry came at the close of the 04:01 breakout candle (high 0.08709, close 0.08705, 392 trades, the busiest candle in the window). That was +0.30% in 3 minutes from 0.08679 (I2-002). The 1m regime was BREAKOUT, with REDUCED_POSITION 60.
- **[AI] Classification:** a policy-scope gap. The early-entry profile admitted a late price through a route that both guards leave out on purpose. It is not a code defect, because the code does what its comments say.

### F5-6 [PE + AI]: price-tick rounding distorts EQ as well as R:R (extends F2-9)

- **[AI]** For coins whose ATR is smaller than one tick, the ATR-based EQ and risk geometry are meaningless. No code checks for this.

### F5-8 [PE code]: how size was set (resolves the 15% figures from F2-13 and F4-4)

- Effective size = round(ATR-plan % × EI %). An ATR-plan value of 0% is treated as 100% (`PaperTradingService.java:328-333`).
- **162 and 182:** 60% × 25% = 15%, which matches the fills.
- **143:** the 1m plan said WAIT_FOR_RETRACEMENT at **0%**, but that became 100% × 25% = 25%.
- **[AI]** A 0% ATR recommendation means "do not enter now", yet the code treats it as "unset". In 143 this sits inside a deliberate override route, so I record it as a semantic risk, not a confirmed defect.

## STATUS AFTER ITERATION 5

**Confirmed defects (unchanged):**
- The boundary lookup race and Replay-parity divergence (F4-2/F4-3), which shaped 143 and 158.
- Label-only 5m authority (F4-4), now confirmed at runtime (F5-9), which shaped 172 and 182.

**New confirmed design weaknesses [PE code], not code defects:**
1. **Low-ATR risk geometry.** The 0.5% stop floor and the 3× ATR target produce R:R below 1 and targets below fees. Five of six trades.
2. **No R:R or fee gate.** R:R only reduces EQ by a flat −30.
3. **EQ scope gap.** BALANCED_EARLY is admitted at LATE_ENTRY through ACCUMULATED_EVIDENCE (162).
4. **ATR-based scoring breaks for coins whose ATR is below one tick** (172).

**New audit gaps:**
- The persisted EQ is not the EQ that admitted the trade (F5-4).
- SETUP_TIMEFRAME_ATR writes no FIX-154 audit row (F5-9).
- The audit's "raw" 5m decision does not capture `original_decision` (F5-9).
- An ATR-plan 0% is treated as 100% when sizing (F5-8, a semantic risk).

**Candidate corrections for the Iteration 8 report (not implemented, no authorisation implied):**
- A fee-aware minimum target and minimum R:R gate, or a target that scales up when the stop is floored.
- Using the same ATR for admission and for the persisted EQ.
- Widening FIX-041's scope to cover ACCUMULATED_EVIDENCE.
- Tick-aware ATR handling.
- A FIX-154 audit row for every BUY route.
- Regression checks: Replay of the six trades, plus the system-wide R:R bucket results from I5-004.
