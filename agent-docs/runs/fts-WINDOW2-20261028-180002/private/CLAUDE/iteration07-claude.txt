### F7-2. 143 was approved on a 5m BUY that the same-boundary 5m signal had already replaced (PROJECT EVIDENCE + AGENT INFERENCE) — CANDIDATE DEFECT

**The two signals:**
- 1m signal #159408 was generated at 19:40:01.633945 UTC (22:40:01 KSA).
- 5m signal #159407 closed on the same 19:40 boundary and was already **WATCH**. It was generated at 19:40:01.635944, which is **2 ms later**, yet it has the **lower id** (I6-003).

**What the code did:**
- `latestAtOrBefore` only accepts signals generated at or before the current one (`:2455-2462`), so #159407 was not visible.
- The code therefore used 5m BUY #159285 instead (19:35:01 UTC → 22:35:01 KSA). It was 300 s old, which is within the 20-minute freshness limit.

**What would have happened otherwise:**
- This route only accepts a bullish 5m signal (`:1486`). With the WATCH signal visible, the route returns nothing.
- #159408 has `atr_immediate_entry_allowed=0`, so the next check rejects with `ATR_ENTRY_BLOCKED` (`:644-648`).
- **AGENT INFERENCE (moderate confidence):** 143 would most likely not have opened. This is not proven, because `deferredContinuationDecision` (`:598`) runs earlier and I have not re-evaluated it (U-I7-4).

**Other context at entry:** price jumped from 3.990 to 4.032 in two 1-minute candles (+1.05%), and the 1m ATR grew about 5× in 7 minutes.

**Classification:** the 5m BUY was stale because of the order in which signals on the same boundary were processed. It is still within the coded freshness rule, so this is a candidate defect, not a confirmed one. How often it happens is requested in I7-003.

### F7-3. 162: whether the age penalty applied came down to 24 ms of processing delay (PROJECT EVIDENCE + AGENT INFERENCE) — CANDIDATE DEFECT

**The timing:**
- Signal 167668's candle closed at 01:02:00 UTC. The signal was generated at 01:02:02.813, a delay of 2.813 s.
- Opportunity 37952 started at 00:41:02.837 UTC (03:41:02 KSA), which means a 2.837 s delay after its own candle closed.
- An opportunity's start time equals the generation time of the signal that opened it. This is proven for 40290 (#176654), 36524 (#159408) and 35535 (#156695). DOGE still needs confirming (I7-001).

**The effect:**
- Measured by generation time, the age is 1259.976 s. `toMinutes()` makes that 20, so no penalty applied (`:948-951,987-989`).
- Measured by candle close, the age is 1260 s, which is **21 minutes**. That gives −5, so the score would have been **45** and the entry blocked as CHASE_ENTRY at both the decision and the fill check.
- The FIX-105 comment at `:894-897` says age is measured "exclusively from … candle-time evidence, never wall-clock". In practice the generation time includes 1.4–2.9 s of processing delay.

**Correction:** the margin is **24 ms**, not the 30 ms I gave in iteration 6.

**Classification:** the code does not do what its comment says, and on this trade that decided the outcome. It is a candidate defect (non-deterministic timing), not a confirmed one.
