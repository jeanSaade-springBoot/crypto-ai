**F3. Nothing closed at a loss between 2026-10-12 10:05 UTC and the snapshot at 2026-10-28 15:00 UTC (PROJECT EVIDENCE plus an UNKNOWN).**
That 16-day gap means one of three things: no trading, only wins, or only STOPPED losses. DB-I1-007 checks which.

**F4. Trade 143: a "hard profit floor" exit with negative P&L (AGENT INFERENCE from code, not yet proven).**
- The floor is `entry × 1.0005` (`LivePositionProtectionService.java:191-199` and `:210-216`; `DynamicProfitLockService.java:164`). It only decides when to exit. The fill happens at the tick price (`closePaper(symbol, price, …)`), so a price gap below entry still produces a loss.
- To reach the rebase path (`:191`), price must have reached TP and triggered a TP extension (FIX-118) within 3.5 minutes. To reach the lock-triggered path (`:210`), price must have hit about 70% of the way to TP.
- I'm not calling this a defect. A loss on this exit is only possible if the exit price fell below entry. Confirmed by DB-I1-005 and DB-I1-008 so far: nothing.

**F5. Live exit inputs are not checked for freshness (code-path observation; whether it mattered for any trade is UNKNOWN).**
- `LivePositionProtectionService.onPrice` (`:95-97`) picks the newest 1m/5m/1h `trade_signal` by `generatedAt` and checks neither age nor `dataQualityValid`.
- `PositionExitPolicy.evaluateNormalExit` (`PositionExitPolicy.java:20-50`) then decides:
  - **HTF_SELL_CONFIRMED** (trade 172): 1h is SELL/STRONG_SELL and 5m is anything except BUY/STRONG_BUY/WATCH.
  - **SELL_CONFIRMED** (trades 182, 158, 137): 1m bearish, 5m bearish, and 1h not bullish.
- Entry, by contrast, requires 5m ≤ 20 min and 1h ≤ 3 h old (TRADING_RULES §4).
- So an exit could rest on an older 5m/1h signal than an entry would accept. This is a hypothesis to test per trade, not a defect.

**F6. Trade 162 closed through the signal path (code evidence).**
- The close_reason `STRONG_SELL` is `signal.getDecision().name()`, set at `PaperTradingService.java:197-208` after `validateSell` passes and only if the profit lock is inactive.
- The exit therefore used `signal.latestPrice`, not a tick (TRADING_RULES §8).
- `exit_signal_id` should be populated for this trade; DB-I1-002 checks it.

**F7. Two losing EGLDUSDT trades about 1h40m apart (AGENT INFERENCE, needs evidence).**
Trade 137 opened at 20:55 UTC and lost; trade 143 re-entered at 22:40 UTC. I'll check whether the second entry's evidence was independent of the first: whether FIX-122 excluded the old evidence (it applies only after a STOP_LOSS, and 137 was SELL_CONFIRMED), and how the 1h context was positioned.
