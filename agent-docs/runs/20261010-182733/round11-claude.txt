**C35 (corrects my round-10 rule).** I proposed: "a candle counts as closed at time *t* only if `closed=1` and `updated_at ≤ t − tolerance`." That rule never says what *t* is, and it mixes clocks:
- **[PROJECT EVIDENCE]** `candle.updated_at` is database time. Every write sets `CURRENT_TIMESTAMP(6)`, and the value stops changing once the row is closed (`CandleRepository.java:140, 162, 187, 202`).
- **[PROJECT EVIDENCE + EXTERNAL RESEARCH, R5]** The possible decision times on `trade_signal` are JVM times:
  - `generated_at` is set in Java;
  - `created_at` uses Hibernate's `@CreationTimestamp`, which by default takes the JVM clock.
- **[PROJECT EVIDENCE]** For `HISTORICAL_ONLY` signals, `generated_at` is the candle's nominal close time, not when Production read anything. The code's own log says so (`CandleClosedAnalysisWorker.java:220`).
- **[PROJECT EVIDENCE]** For the period since V108, there is a timestamp on the same database clock: `candle_analysis_outcome.created_at` is `CURRENT_TIMESTAMP(6)`. A row is written for skipped candles, historical-only work and each signal's processing outcome.
- **[AGENT INFERENCE]** A safer rule, using database time throughout:
  - **Lower bound L:** the analysed candle's own `updated_at`. Its analysis can't start before its close is written.
  - **Upper bound U:** the `created_at` of that candle's outcome row.
  - A context candle X counts as visible if `X.updated_at + δ ≤ L`, and as not visible if `X.updated_at ≥ U`.
  - Anything in between is ambiguous: refuse the strict claim, or declare it as a simulation assumption.
  - Before V108, the only upper bound is the JVM-clock `trade_signal.created_at`. Those windows need a measured clock-skew bound, or refusal.
  - δ covers the gap between when a statement starts and when it commits. It must be measured, not assumed.
