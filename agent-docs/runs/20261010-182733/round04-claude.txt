## FINDINGS

### A. Common ground (re-checked, still holds)
All **[PROJECT EVIDENCE]**.
- **Read/write boundary is wrong:**
  - `regression_test_run` doesn't exist; the table is `analysis_test_run`.
  - A run writes 12 tables, not the 4 listed.
  - `fix122_evaluation` is written in a separate transaction that survives rollback.
  - The run chart reads Production `wallet_trade`.
- **No staging or publication contract.** There are no staging tables, publication transaction or terminal-state rules.
- **`ANALYSIS_PARITY` is undefined.** `ReplayParityValidator` has no Java caller and no test.
- **Null Replay signal IDs** switch off Near-TP harvest and the BUY_CONTINUATION rule. The no-HTTP change must land before stable IDs; Codex now agrees.
- **Production signal-path order** is: advisory stop → TP (no extension) → label-free lock → stop loss → rebase floor → SELL (suppressed while a lock is active) → add (also suppressed while a lock is active). Codex's Round-4 order now matches.
- **Admission:** the request has no mode or profile field, and the run and revision rows are written before the worker starts.
- **Deployment:** Jenkins deploys LIVE right after `mvn clean package`. There is no approval stage and no automatic rollback.
- **Governance:** the spec must sit at the canonical path, and the dirty worktree must be frozen before approval.

### B. New evidence this round

**N11. The spec's "EXPERIMENTAL" doesn't match the code, and some current labels are false.**
- **[PROJECT EVIDENCE]** No code ever opens an `EXPERIMENTAL` Replay scope; both callers use the default `PRODUCTION_PARITY`. So:
  - the experimental branches in `RegimeStateService` and `EntryAuthorityService` can never run;
  - `RegimeStateService.replayState` is never written, so RPR6-12 and M08 target dead state.
- **[PROJECT EVIDENCE]** Every run is labelled `replay_logic_mode=PRODUCTION_PARITY`, even when `fix122Enabled=false` turns FIX-122 entry evaluation off for that run. Pre-FIX-122 runs are mislabelled today. The spec says they "remain explicit EXPERIMENTAL" but registers no change to where the label comes from.
- **[PROJECT EVIDENCE]** Replay's FIX-122 switch defaults to `true` per run; it doesn't follow Production's `trading.fix122.enabled`.
  - **[AGENT INFERENCE]** The virtual profile or certificate must carry that value, and C01–C04 don't.
- **[PROJECT EVIDENCE]** The FIX-11K and FIX-11Q observers run in every baseline run. They only observe and write separate tables.
  - **[AGENT INFERENCE]** X08 ("baseline never invokes") is therefore a behaviour change to RPR6-06. It must also cover `DefensiveRiskReductionReplayObserver`, which isn't registered.

**N12. Order-book context differs in every era, not just old windows.**
- **[PROJECT EVIDENCE]** When the observation window is empty:
  - Production returns `INSUFFICIENT_DATA_HOLD` with entry **disallowed**;
  - Replay returns `UNAVAILABLE` and leaves entry permission unchanged;
  - `FinalDecisionService` combines that permission into `entryAllowed`.
- **[PROJECT EVIDENCE]** Production saves order-book samples asynchronously and best-effort. A full queue or a failed insert drops the row with only a WARN log.
- **[AGENT INFERENCE]** Replay can therefore see fewer samples than Production used, with no durable record of the loss. That can change:
  - `liquidityStatus`, which the validator compares for exact equality;
  - the 12% liquidity weight in confidence;
  - whether a BUY is allowed.

  Spec §2 treats this as an old-window problem only.

**N13. Sentiment has no durable "available since" time in any era.**
- **[PROJECT EVIDENCE]** `sentiment_signal` has no storage-time column.
  - FEAR_GREED stores the provider's timestamp; CRYPTOPANIC and NEWS_API store the article's publication time.
  - Replay selects rows by `observed_at ≤ decision time`.
- **[AGENT INFERENCE]** Any row collected after its stated time leaks into earlier Replay decisions (look-ahead), and no as-of rule can prevent it. This matters only if sentiment is enabled in Production, which I couldn't check.
- **[PROJECT EVIDENCE]** `trade_signal` stores each signal's sentiment, liquidity, derivatives and BTC outcomes. So M03's "stored as-of evidence" route exists, but the spec has to name it.

**N14. "Exact price" mode is decided once for the whole run.**
- **[PROJECT EVIDENCE]** A single accepted price event anywhere in [start − 3 h, end] does three things for the whole window:
  - labels the run `EXACT_PRICE_REPLAY`;
  - lets it pass as `test_passed`;
  - turns off the signal-price fallback.
- **[AGENT INFERENCE]** During any gap in price evidence (downtime, the V64 boundary, excluded statuses), the virtual position gets no TP/SL/lock checks until the next event, while the run still claims exact price parity. The qualifier has no coverage or continuity rule; X03 covers excluded statuses only.

**N15. Replay and Production behave differently while a profit lock is active.**
- **[PROJECT EVIDENCE]** Replay's exact-price branch exits through `validateSell` and adds to the position without checking for an active lock. Production suppresses both.
- **[PROJECT EVIDENCE]** Production's signal path also has a label-free lock exit that Replay never runs.
- **[AGENT INFERENCE]** M06 covers these only in general terms; X06 needs them as named test fixtures.

**N16. Shared-market LIVE mode adds Replay reads and writes missing from §3.**
- **[PROJECT EVIDENCE]** In LIVE mode, Replay writes `shared_candle_input_audit` in a separate audit transaction and reads `shared_market_cutover_history`.
- **[AGENT INFERENCE]** The spec must either limit Replay to OFF mode or list both tables.

**N17. The advisory stop depends on its reason code and on the signal ID.**
- **[PROJECT EVIDENCE]** FIX-122 stop boundaries are recorded only for reason `STOP_LOSS`. `POSITION_STOP_LOSS` is deliberately excluded, both in Production and in the Replay scope.
- **[PROJECT EVIDENCE]** `PositionManagementService.validSignal` requires a non-null signal ID, which is another null-ID shortcut.
- **[AGENT INFERENCE]** If Replay adds the advisory stop without keeping its distinct reason code, it will create FIX-122 boundaries that Production never had.

**N18. Replay and Production use different clocks, regardless of when the closing message arrives.**
- **[PROJECT EVIDENCE]** In Production:
  - a live signal's `generated_at` is the wall-clock time of analysis;
  - entry and add prices are looked up at `Instant.now()`;
  - the price path reads the latest committed signal, so a new signal is visible only after the asynchronous analysis commits.
- **[PROJECT EVIDENCE]** In Replay:
  - `generated_at` and the price lookup both use the candle's nominal close;
  - the new signal becomes visible to the price path as soon as the events up to the close have been processed.
- **[AGENT INFERENCE]** These differ even if the closing message lands exactly on the close. Production's stored `generated_at` and `created_at` are the "recorded ordering" that §7 asks for.

**N19. There is no way to discard one run's data.**
- **[PROJECT EVIDENCE]** Delete Data runs unconditional DELETEs across every run. After a restart, interrupted runs are marked ERROR but keep their partial rows.
- **[AGENT INFERENCE]** M04's "discard staged artifacts" needs a new per-run mechanism, and the spec doesn't define one.

**N20. A contradiction to report, not resolve.**
- **[PROJECT EVIDENCE]** AGENTS.md:118-121 says V103 still needs the collector table on a fresh install, and treats trader-only bootstrap as a release blocker.
- **[PROJECT EVIDENCE]** The current code has a B105 trader-only baseline, whose header says V103 has no baseline effect. An opt-in real-MySQL test runs Flyway migrate and validate on a fresh database and checks that V106 succeeds.
- **[AGENT INFERENCE]** D02/X11 must say which install policy they rely on. Whether the AGENTS.md blocker is resolved needs dual-agent review.

### C. Corrections to my Round-3 findings
- **C6 — N6 was wrong as stated. [PROJECT EVIDENCE]**
  - Both modes loop over the same unfiltered candle list, and both calculate indicators from closed candles only. DATASET differs only in using a preloaded dataset and lineage map.
  - For a `closed=0` row, both modes produce a signal from the previous closed candle. `analysis_test_signal` records the open candle's open time; `trade_signal_test` records the previous candle's.
  - M02 must fix this in both modes.
- **C7 — N4 was partly wrong. [PROJECT EVIDENCE]**
  - Fundamentals: `observedAt` is set when the row is saved (`FundamentalService:37`), so there is no look-ahead.
  - Previous indicator: `previousSnapshot` reads the same Production `technical_indicator` row Production used. The only risk is a row saved after the decision, and `created_at` exists to rule that out.
  - Sentiment: the concern stands and is stronger (N13).
- **C8 — Wrong: "no real-MySQL test infrastructure for X11". [PROJECT EVIDENCE]**
  - Opt-in Maven profiles `fix132-mysql`, `fix142-mysql` and `fix153-mysql` exist.
  - `LocalCandleMySqlIT.freshFlywayBaselineUsesOnlyTraderSchema` runs a fresh migrate and validate on MySQL.
  - The real gap is that X11 doesn't name or extend these, and CI never runs `*MySqlIT`.
- **C9 — N2 understated. [PROJECT EVIDENCE]**
  - For BALANCED, HEALTHY, FRESH, CROWDED, and NOT_APPLICABLE after a 400, the confidence shift is at least 2.4 points, so the rounded `rawConfidence` *always* changes, not "usually".
  - LEARNING, SHORT_COVERING and live UNAVAILABLE shift it by less than 1 point.
- **C10 — Overstated: the `fix122_evaluation.signal_id` collision risk.** **[PROJECT EVIDENCE]** Replay rows are already told apart by `test_run_id`, and every reader filters on it. This is not a defect.
- **C11 — Precision fixes. [PROJECT EVIDENCE]**
  - The 60 s and 15 min blocks are defaults; a `Retry-After` header overrides them.
  - C3: the daily-statistics row is created inside `executeBuy`, which progressive adds also use.
- **C12 — Retracted and softened.**
  - My D5 line-number point was immaterial; `AGENTS.md:327` is the operative sentence.
  - Logging: Production log levels are unverified, so the spec must say how `REPLAY_DECISION` is enabled rather than assume it's invisible.

## OBJECTIONS
**Material (blocking).** Each is either new or refined this round.

1. **Governance.**
   - Put the exact revision at `agent-docs/FINAL_CHANGE_SPECIFICATION.md`.
   - Freeze the commit plus a manifest of the dirty worktree before approval.
   - Replace "supersedes … for review only" with a plain statement.
2. **Allowlists.** Give a complete read/write/state list for every run, archive, purge and Proven path, including:
   - the `fix122_evaluation` write that survives rollback and the `wallet_trade` chart read;
   - the shared-market LIVE-mode tables (N16), or a restriction to OFF mode;
   - availability-time rules for `technical_indicator` (`created_at`) and sentiment, the latter being impossible without a stored outcome (N13);
   - shared in-memory state (`Fix154Metrics`) and the shared REST gate.
3. **Registry.**
   - Add `RegressionTestService`, the controller, request and UI, the investigation-case path, `ReplayDataSource`, `DefensiveRiskReductionReplayObserver`, `OrderBookLiquidityService` / `OrderBookSnapshotService`, `SentimentService`, `MarketPriceEventService`, `StopLossEvidenceService` / `Store`, `EntryConsumptionPolicy`, `NearTpFailureProtectionPolicy`, the FIX-154 classes, `pom.xml` profiles and the Jenkinsfile.
   - Retarget or drop RPR6-12 (dead state, N11).
   - Give an "unchanged because…" entry for every class deliberately left alone.
4. **Identity.**
   - A Replay ID namespace.
   - The full null-ID inventory above, with each shortcut replaced by an explicit Replay check.
   - The no-HTTP change (RPR6-10) ordered before stable IDs (RPR6-05).
   - Run identity that survives Delete Data (N5).
   - Relabelling of existing runs: null-ID runs, and pre-FIX-122 runs labelled `PRODUCTION_PARITY` (N11).
5. **`ANALYSIS_PARITY` oracle.**
   - Match key: symbol, timeframe and `candle_open_time`.
   - Which Production signals are eligible, by `signal_mode` and era.
   - A versioned field set with tolerances.
   - For each dependency, one route: inject the stored outcome, recompute, or exclude/refuse. The spec must state that order-book completeness can't be proven (N12) and sentiment can't be reconstructed (N13).
   - Refusal codes.
6. **Clock and order model.**
   - Decision, fill and signal-visibility clocks (N18).
   - Closing-tick precedence, measured from FIX-131 logs.
   - Exact signal-path and price-path orders, with named fixtures for N15 and N17.
   - The same-boundary higher-timeframe rule, using stored `generated_at`.
   - Daily budget and daily-loss semantics.
   - How the global max-open-positions limit applies to a single-symbol account.
7. **Production admission outcomes.** For `DATA_QUALITY_BLOCKED`, `HISTORY_UNAVAILABLE`, `HISTORICAL_ONLY`, `EXPIRED` and `REVIEW_REQUIRED`, state whether Replay reproduces, recomputes or refuses each one.
8. **Price-evidence coverage (N14).** Coverage must be judged per segment and by era (V64, FIX-153), not as one flag for the run. Gaps must change the published label.
9. **Staging and terminal states.**
   - A per-run discard and publish mechanism (N19).
   - Crash/restart and cancellation behaviour.
   - Treatment of writes that survive rollback.
   - Run status kept separate from the parity label, with mappings for `status`, `test_passed`, `replay_price_mode` and `replay_logic_mode`.
10. **Isolation enforcement.**
    - Name the enforcement point and make it fail closed across threads.
    - Profile-dated minimum notional and the FIX-122 flag in the profile.
    - Code rollback for the shared classes, given automatic LIVE deployment.
    - A numeric latency budget.
    - A transaction and lock-order test for the shared classes.
11. **Labels (N11).** Fix where `replay_logic_mode` comes from, and define "EXPERIMENTAL" separately for each mechanism: the scope mode, the observers, and the FIX-122 revision.
12. **FIX-154.** Treat it as current behaviour and register its reproduction, audit and metrics in Replay.
