## FINDINGS

- **PROJECT EVIDENCE:** RPR-0.6 is not the canonical approval contract required by governance. Governance names `agent-docs/FINAL_CHANGE_SPECIFICATION.md`, which remains RPR-0.4; RPR-0.6 says it supersedes earlier revisions “for review only.” Its approval therefore cannot authorize the specified design process.

- **PROJECT EVIDENCE:** The “complete” registry is incorrect. It names nonexistent `regression_test_run` rather than `analysis_test_run`, and omits `RegressionTestService`, which creates runs and owns cancellation, purge, archive, and ID-reset behavior.

- **PROJECT EVIDENCE:** M02 does not prevent historical look-ahead. It only requires a candle be `closed=1`; it does not require that the candle was closed when Production made the decision. Current reconciliation can later close an open row or add a closed backfill. The `Candle` projection does not expose `created_at`, `updated_at`, provenance, or reconciliation resolution time needed to establish historical visibility.

- **PROJECT EVIDENCE:** The present Replay timeline is not even restricted to closed candles: it loads all candles by identity. Snapshot queries then apply the row’s current `closed=1` state. Production data quality likewise evaluates currently closed rows. The proposed qualifier must define and enforce one decision-time finality rule across every Replay and shared candle read.

- **PROJECT EVIDENCE:** Isolation is specified as an outcome, not an enforceable design. Current Replay reads `wallet_settings`; minimum-notional evaluation may call Binance HTTP; the existing wallet guard only protects writes and locking reads. RPR-0.6 does not define dependency wiring, propagation across async work, or a complete interception boundary.

- **PROJECT EVIDENCE:** RPR-0.6 requires retained price-event ID/order data, but the current `PriceEvent` query orders by `id` while discarding it from the returned record. `MarketPriceEventService`/`PriceEvent` are absent from the change registry, so the required behavior is unregistered.

- **PROJECT EVIDENCE:** M04’s staging requirement is not implementable as specified. Current Replay writes output incrementally during processing. The artifact does not define staging table names, promotion transaction, cancellation/restart/purge behavior, or treatment of independently committed diagnostics/audits.

- **PROJECT EVIDENCE:** The artifact conflicts with the requested “Production code unchanged” boundary: it authorizes modifications to shared Production services, while omitting existing shared dependencies such as `ExecutionIntelligenceService` and `ExecutionPriceAuthorityService`. It must explicitly choose Replay-local adapters only, or authorize narrowly defined shared refactors with equivalence proof.

- **PROJECT EVIDENCE:** `ANALYSIS_PARITY` is not presently grounded in a version/config identity source. The artifact acknowledges missing deployed JAR/config lineage but defines no evidence source or refusal algorithm that makes this claim safely attainable.

- **AGENT INFERENCE:** These are material design omissions, not implementation details. The specification is not complete or safe for dual-agent technical-design approval.
