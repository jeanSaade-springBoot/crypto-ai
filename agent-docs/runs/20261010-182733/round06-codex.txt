- **[PROJECT EVIDENCE]** RPR-0.6 is not a valid approval artifact yet. Governance requires the approved contract at `agent-docs/FINAL_CHANGE_SPECIFICATION.md`, which remains RPR-0.4; RPR-0.6 is separate and no corresponding frozen PDF exists. Its plan to re-hash the dirty worktree only immediately before implementation cannot freeze the precise state reviewed for approval.

- **[PROJECT EVIDENCE]** The read/write registry is inaccurate and incomplete. The current run table is `analysis_test_run`, not `regression_test_run`. Current Replay also creates `fix122_replay_revision`, writes `fix122_evaluation`, archives multiple tables, and its detail endpoint reads Production `wallet_trade`. The proposed boundary must explicitly classify each of these.

- **[PROJECT EVIDENCE]** M04 cannot be safely approved as written. Replay currently publishes rows during candle processing, while `StopLossEvidenceStore.append` uses an independent `REQUIRES_NEW` transaction. “Discard staged artifacts” has no defined schema, publication transaction, terminal state model, recovery rule, or treatment of independent writes.

- **[PROJECT EVIDENCE]** M05’s named-exception isolation mechanism is not fail-closed in the current call graph. `BinanceMinimumExecutionPolicy` catches HTTP failures and returns an ordinary policy result; the worker catches generic per-candle exceptions and continues. The design needs a run-level violation state checked before publication, plus tests through every swallowing boundary.

- **[PROJECT EVIDENCE]** M02’s `closed=1` admission rule is too weak for Production-analysis parity. Runtime dispatch requires a close-transition token and excludes `BACKFILL`; authoritative recovery can close a candle without a token. RPR must distinguish history inputs from executable/live decision points and specify treatment of pre-V106 NULL provenance.

- **[PROJECT EVIDENCE]** M06 does not reproduce either current ordered route completely. Live protection can extend TP before exit, then applies stop, profit-lock/rebase, normal exit, and near-TP logic. Signal processing has a different order: TP, lock, stop, rebase floor, lock-active SELL suppression, then add. The specification’s merged “price then signal” sentence omits required route-specific state transitions and reason-code behavior.

- **[PROJECT EVIDENCE]** Price-event identity promised in §3/L03 is unavailable from the current `PriceEvent` object. SQL orders by `observed_at, id`, but the returned record exposes only timestamp, price, and source; it carries neither ID, status, nor `ordering_slot`. `MarketPriceEventService` is absent from the registry.

- **[PROJECT EVIDENCE]** “Single symbol” is incomplete: Replay currently loads BTC candles and builds BTC signals for context. Qualification and ordering must include reference-symbol candles/signals and define same-close visibility across symbols.

- **[PROJECT EVIDENCE]** Current source includes FIX-154 behavior in `TradeExecutionValidationService`; RPR does not register the higher-timeframe assessment, audit, metrics, or Replay evidence treatment. This conflicts with the repository instruction calling FIX-154 pending, so current source—not the documentation—must drive the revised parity scope.

- **[AGENT INFERENCE]** V109 adds columns to `trade_signal_test` but not its archive, while archive uses positional `INSERT … SELECT ?, r.*`. A fully migrated database is likely to reject archive writes for column-count mismatch. RPR’s migration proof should explicitly validate active/archive column parity and archive new certificate/audit evidence.
