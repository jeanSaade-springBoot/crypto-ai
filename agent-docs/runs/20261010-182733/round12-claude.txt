### C. New findings

**N56 (moderate; sharpens 8, 11, 15, 24 and N54). Without price events Replay can never trade, so Production's signal-path hard exits never run in Replay.**

- **[PROJECT EVIDENCE]** How it works today:
  - `exactPriceReplay = !livePrices.isEmpty()` is set once per run (`ShadowProductionReplayService.java:95`). It isn't just a label: the signal-close protection block runs only when it is false (`:183`).
  - Opening or adding to a position needs a fresh execution price (`:310-312`, `:345-347`). In Replay that price comes only from `replayScope.latestPrice()` (`ExecutionPriceAuthorityService.java:37-43`).
  - `latestPrice` is set only by `referencePrice(...)` (`ExecutionReplayScope.java:73-77`), and its only caller is the price-event loop (`:130`). Every run starts with it null (`ExecutionReplayScope.java:37-45`).
- **[AGENT INFERENCE, deduced from the code above]** Consequences:
  - A window with no accepted price events can never open a position. Every `SIGNAL_PRICE_FALLBACK` run reports zero trades.
  - An open position means at least one event was consumed, so `exactPriceReplay` is always true when a position is open. The block at `:183-230` never runs. It contains `evaluateExit`, the signal-path profit-lock update and FIX-11T's fallback Near-TP.
  - The comments describing that fallback (`:85-88`, `:184`, `:215-217`; `RegressionTestWorker.java:190-193`) describe behaviour that never happens.
- **[PROJECT EVIDENCE]** What actually diverges is an omission:
  - **Production's signal path** runs `POSITION_STOP_LOSS`, take-profit, stop-loss, the rebase hard floor and the profit lock when the signal price is authoritative, then `validateSell` (`PaperTradingService.java:113-205`).
  - **Replay's reachable signal path** runs only `validateSell`, and only for a bearish 1m signal (`:232-255`).
- **[AGENT INFERENCE]** What RPR-0.6 must add:
  1. **A price-assumption model, or refusal.** M06 says "Simulation records price assumptions" but names no mechanism. §7 requires "the same extracted pure policies", and Production's price policy refuses an entry without an event under 15 s old (`ExecutionPriceAuthorityService.java:25, 46-48`). So `PRODUCTION_LOGIC_SIMULATION` will produce zero trades wherever there are no events. The revision must choose one:
     - declare a fill assumption that isn't Production's (for example, candle close plus profile slippage), with its own label;
     - or refuse those spans, or mark them analysis-only, and report the refusal rate (O14).
  2. **X06 fixtures taken from Production.** The signal-path cases (take-profit, stop-loss, floor, lock, `POSITION_STOP_LOSS`) must come from `PaperTradingService`, not from Replay's dead block. RPR6-06 must register removing or rewriting that block and its comments. Removing it takes away no `wallet_settings` read, because the price path also calls `profitLockState` and `rebaseForExtendedTarget` (`:415`, `:448`).
  3. **Old run labels (objection 11).** `replay_price_mode` is stored on each run (`RegressionTestWorker.java:205-206`).
     - Existing `SIGNAL_PRICE_FALLBACK` runs have zero trades by construction.
     - `EXACT_PRICE_REPLAY` is set whenever at least one event existed, even if most of the window had none.
  4. **Coverage per span, not one flag per run.** Together with N54, this is the coverage model the qualifier needs.
- **[PROJECT EVIDENCE]** The gaps aren't caused by purging: nothing in `src/main` deletes `market_price_event` rows. Invalid observations are never stored (`MarketPriceEventService.java:50-58`), so Production applied no protection from them either.

**N57 (minor; extends N51/N51a). The spec defines "Replay" by name, not by component.**
- **[PROJECT EVIDENCE]** `com.crypto.service.TradeReplayService.replay(positionId)` loads a Production `paper_position` (`:36-37`) to build a Production trade timeline. It is an inspection view, not the regression Replay.
- **[AGENT INFERENCE]** §1 and §3 ban account reads "in Replay". The revision should define the boundary by package and entry point: the regression worker, shadow service, observers and `/runs/**`. Otherwise a source-scan guard (N45) will flag this class or miss Replay code elsewhere.
