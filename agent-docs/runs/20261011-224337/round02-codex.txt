## OBJECTIONS

- [PROJECT EVIDENCE] The draft simultaneously forbids account-table reads, forbids Production changes, and keeps shared BUY validation in the Replay path. It must instead require a fully Replay-local/version-matched BUY-validation mirror, or classify all affected decisions non-comparable. Allowing the current shared account read is incompatible with the stated boundary.

- [PROJECT EVIDENCE] `ANALYSIS_PARITY` explicitly disclaims lifecycle claims, while the acceptance rule requires lifecycle parity. The specification must define whether lifecycle is only a separately reported metric or introduce a compatible non-wallet lifecycle label.

- [PROJECT EVIDENCE] `POSITION_STOP_LOSS` can be executed before normal Production processing, but is absent from the per-exit-class and critical-safety lists: [PositionManagementService.java](C:/workspace/crypto-ai-trader-mysql/src/main/java/com/crypto/position/service/PositionManagementService.java:129).

- [AGENT INFERENCE] A raw 98–99% percentage would be misleading unless denominator coverage, minimum comparable cases, the lower-confidence-bound method, and a pre-committed final evaluation window are frozen before measurement.

- [PROJECT EVIDENCE] The working tree is materially dirty, so it does not establish identity with the archived packages cited by the draft. Freeze the exact source/configuration/migration/worktree baseline before re-verifying the registers.
