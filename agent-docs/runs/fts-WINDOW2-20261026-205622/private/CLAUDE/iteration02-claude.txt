**F-5 — Main finding: in quiet markets the stop is wider than the target** (PROJECT EVIDENCE: code + DB; arithmetic is AGENT INFERENCE)
- The code (`AtrRiskService.java:34-45`; `application.yml:137,138,143`) sets:
  - stop distance = the larger of 2×ATR and 0.50% of price
  - target distance = 3×ATR, with no lower limit
  - ATR is the average true range, a measure of recent price movement.
- So whenever ATR is below 0.25% of price, the 0.5% stop applies and the reward-to-risk ratio falls below 1.
- The only minimum-ratio check I found is `BREAKOUT_RETRACEMENT_MIN_RR = 1.15`, at `ExecutionIntelligenceService.java:212,1539`. It applies only to breakout retracement entries.
- Recomputed from the stored values:

| 137 | 0.11% | 0.50% (floor) | +0.322% | 0.64 | 61% |
| 143 | 0.27% | 0.565% (2×ATR) | +1.768% (stored) / +0.786% (signal) | 3.13 / 1.43 | — |
| 158 | 0.05% | 0.49% (floor, set from the signal price) | +0.171% | 0.35 | 74% |

- **Assessment:** this is a configuration/design issue, not a coding bug. The stop and target behave exactly as coded.
- Without fees, a target-or-stop system on these trades needs a 57–74% win rate. With fees it needs more.

**F-6 — Three targets were below or close to the fee cost** (AGENT INFERENCE, building on F-4 and F-5)
