## FINDINGS

**F-0 — The snapshot timestamps don't agree with each other** (AGENT INFERENCE, based on PROJECT EVIDENCE)
- `CHARTER.md:4-5` lists 18:07:57 UTC and 20:56:22 KSA.
- 18:07:57 UTC is 21:07:57 KSA, and 20:56:22 KSA is 17:56:22 UTC.
- The run ID `20261026-205622` matches the KSA value, so the UTC value is probably the wrong one. This is not confirmed.
- **Impact:** a trade with `closed_at` between about 17:56 and 18:08 UTC could be in or out of the window depending on which value is right. DBQ-CLAUDE-I1-002 checks for that.

**F-1 — The selection rule misses all stop-loss losses** (PROJECT EVIDENCE)
- The frozen set uses `status='CLOSED'`.
- In the code, every stop-loss exit writes `PositionStatus.STOPPED`, not `CLOSED`:
  - Live protection: `LivePositionProtectionService.java:178`
  - Signal path: `PaperTradingService.java:183`
  - Manual close at or below the stop loss: `PaperTradingService.java:433`
- `PositionStatus` has four values: `{OPEN, CLOSED, STOPPED, CANCELLED}` (`domain/PositionStatus.java:2`).
- **So the six frozen trades are the most recent losses that did *not* end on a stop loss.** They can only come from:
  - a validated SELL or STRONG_SELL signal (`PaperTradingService.java:207`)
  - a higher-timeframe or signal-confirmed normal exit (`LivePositionProtectionService.java:238`)
  - a profit-lock exit (`:223`, and the signal path `PaperTradingService.java:452-470`, which closes at `signal.latestPrice`)
  - a profit-lock hard exit, which by design fires below entry × 1.0005 (`:196`, `:214`, `PaperTradingService.java:193`)
  - a manual close above the stop loss
  - a near-TP partial harvest followed by an adverse remainder
- This is not grounds to change the frozen set. The coordinator should note it as a selection limitation. DBQ-CLAUDE-I1-002 measures how many STOPPED losses fall in the same period.

**F-2 — "Protected" exits can book losses** (PROJECT EVIDENCE + AGENT INFERENCE)
- `closeFromProfitLock` uses `signal.getLatestPrice()` as the exit price (`PaperTradingService.java:457`). That is the closing price of the signal's candle, not a live tick.
- A profit-lock or hard-floor exit can therefore record a price below entry when the price drops sharply.
- A loss on a trade closed as `PROFIT_LOCK*` would mean the protection lagged or the exit price was stale. A loss on a `SELL`/`HTF` exit could just be a legitimate strategy exit.
- Each of the six trades needs classifying this way once the data arrives.

**F-3 — P&L is gross of fees** (PROJECT EVIDENCE, `claude-docs/INVESTIGATION_LOG.md` item 2)
- Automatic wallet trades record `fee_usdt=0`.
- The real losses are larger than `realized_pnl`, so fees will be recomputed separately.

**F-4 — Paper and wallet records can diverge** (PROJECT EVIDENCE, earlier observation)
- If the wallet exit fails, the paper position still closes.
- Each paper close needs to be matched against its SELL rows in `wallet_trade`.
