## OBJECTIONS

1. **No safe "finish" without the canonical contract.** Under JEAN_REVIEW, the scope must be traceable to a frozen revision. Install RPR-0.9.12 (with its hash) in the repository first; until then, completeness can't be checked against it.
2. **The BUY mirror is the critical path and has no design.**
   - The choice is between copying `ExecutionIntelligenceService.evaluateBuy`, `TradeExecutionValidationService.validateBuy` and the gates around them into Replay, or changing a Production class (forbidden).
   - A copy brings a drift risk: Replay could diverge from future Production changes and still pass its own tests. That needs a Production-change parity test rule, which no registry item covers.
3. **The guard can't be made true by adding more call-site checks.** With 123 raw calls, the only credible design is:
   - a single Replay data-access class that owns all SQL text and maps each statement constant to one `Operation`;
   - a static test that bans `JdbcTemplate` and repository imports in every Replay-reachable class outside that layer.
   Anything less is honor-system again.
4. **F8 must be fixed before any profile is written.** One option is to purge `replay_*` in Delete Data. Another is to key profiles on a unique run identifier (for example a UUID or hash) rather than the reusable auto-increment ID.
5. **The wallet-shaped profile fields contradict D35 and RET-01.** Either the sizing primitives are removed, or the specification has to say why reserve, base amount and daily cap are "policy" rather than wallet state.
6. **Removing wallet simulation, `*_test` writes and the fallback exit path changes what Replay outputs.** Historical runs then can't be compared with new ones. That needs an explicit output-version marker, which no registry item covers.
