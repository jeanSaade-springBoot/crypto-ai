## ⚠ FINDING F0 — Timezone contradiction (blocks the timeline labels)

**PROJECT EVIDENCE**
- The app writes timestamps in UTC. `application.yml:22-25,35` sets `SET time_zone='+00:00'`, `connectionTimeZone: UTC`, `forceConnectionTimeZoneToSession: true`, and `hibernate.jdbc.time_zone: UTC`.
- The columns are `timestamp(6)` (prior run, DBQ-CLAUDE-I1-007). MySQL stores these in UTC and **displays them in the session's time zone**.
- The query wrapper `scripts/agent-db-query.ps1` never sets `time_zone`, and it rejects `SET` statements. A grep of `scripts/` found no time_zone setting in it.
- Two values for the same moment disagree by exactly 3 hours. `wallet_trade.execution_message` is Java's `Instant.toString()`, which is always UTC (`...Z`). The `execution_price_observed_at` column, as the wrapper shows it, is 3 hours later:

| wallet_trade | Java message (UTC, `Z`) | Wrapper-displayed column |
|---|---|---|
| 344 (trade 137) | `2026-10-11T17:55:00.032Z` | `2026-10-11 20:55:00.032` |
| 392 (trade 158) | `2026-10-11T23:35:00.328Z` | `2026-10-12 02:35:00.328` |
| 426 (trade 172) | `2026-10-12T03:36:01.457Z` | `2026-10-12 06:36:01.457` |
| 451 (trade 182) | `2026-10-12T06:57:02.437Z` | `2026-10-12 09:57:02.437` |

**AGENT INFERENCE (high confidence, not yet proven)**
- The wrapper session probably runs at +03:00, the host's KSA zone. If so, wrapper-displayed values are already KSA, not UTC. That contradicts the rule "Raw MySQL timestamps are UTC" for this access path.
- The charter header is also inconsistent: "UTC 11:54:53" and "KSA 12:31:38" are 36m45s apart, not 3 hours. One reading that fits: 11:54:53 is DB `NOW()` shown in KSA, and 12:31:38 is when the charter was written.

**Labelling in this report:**
- "DISP" = the wrapper-displayed value.
- "UTC*" = DISP − 3h, provisional.
- "KSA" = UTC* + 3h, which equals DISP.

DBQ-CLAUDE-I1-001 settles this. Under the old convention (DISP is UTC), every KSA time below would be 3 hours later. This affects both agents and every earlier study, so it needs dual review before anyone relies on it.
