FIX-149 — Fresh admission indexes (corrected two-schema deployment)

Confirmed from the user's live MySQL results and failed startup log:
- JohnnyM:3307 trader schema: crypto_ai.
- Collector event table: crypto_ai_v2.market_data_stream_event (InnoDB).
- crypto_ai.flyway_schema_history has installed_rank=103/version=103/success=0.
- The original V103 failed its table prerequisite BEFORE any index ALTER ran.

Correction
The original package incorrectly assumed the source table shared the trader
schema and changed the source-read default accordingly. This revision restores
source reads to crypto_ai_v2. spring.datasource remains crypto_ai. V103 still
runs through the trader's normal classpath:db/migration Java Flyway discovery
and records its outcome in crypto_ai.flyway_schema_history, but every table/index
metadata query and its ALTER explicitly target crypto_ai_v2 on that same MySQL
server. No second Flyway runner/history is introduced. V1–V102 remain unchanged.
No automatic schema discovery, empty replacement table, table copying or data
retirement occurs. This corrected V103 is for the confirmed local two-schema
layout; a collector on another MySQL server requires its owner's migration flow,
not this cross-schema DDL. Local Flyway credentials need ALTER access to the
collector table; a SELECT-only source credential is not used for the DDL.

Adds, in one online ALTER when both are missing:
idx_stream_fresh_observed:
  symbol, interval_code, source, classification, observed_at, symbol_sequence
idx_stream_fresh_closed:
  symbol, interval_code, closed, source, classification,
  candle_close_time DESC, symbol_sequence ASC

Matching manually-created indexes are accepted only with exact key-part order,
direction, visible non-unique BTREE and no prefixes. Same-name mismatches fail,
never silently drop/recreate. Missing collector table and wrong trader/history
schema fail before ALTER. MySQL 8 is required. ALGORITHM=INPLACE, LOCK=NONE
refuses an unsupported fallback. Metadata-lock wait is limited to 10 seconds and
the original session setting is restored; this does not limit index-build time,
resource cost or every InnoDB wait. DDL commits implicitly. Start/end UTC,
duration, outcome and SQL state are logged with FIX-149 tags.
