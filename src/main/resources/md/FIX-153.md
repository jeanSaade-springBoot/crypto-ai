# FIX-153 — local candle runtime

Production now defaults to trader-owned Binance ingestion and local `crypto_ai` candle reads. OFF disables the collector pool and shared scheduling. Existing shared evidence remains retained. No manual review state becomes authority to replay an unknown attempt.

The revision-17 implementation adds monotonic atomic candle writes, immutable ingestion provenance, a unique canonical price receipt, atomic protection/APPLIED completion, bounded automatic PENDING classification, latest-pending 1m/FIFO higher-timeframe admission and a bounded RUNTIME-only close detector. First direct automatic attempts check freshness after consistency locks. LIVE/HISTORICAL_ONLY markers distinguish physical generation latency from historical as-of clocks. V106 adds the evidence columns and a local latest-signal index. B105 supports empty trader-only installation; old migrations are unchanged.

Logs distinguish input commit, protection outcome commit, uncertainty, no replay resolution, queue admission/replacement/rejection and worker return. DEBUG captures event identities; INFO emits aggregate counters every minute. Elapsed callback/JDBC times include waits and are not server execution times. UTC/KSA labels are explicit.

The standard Java 21 suite passes; detailed counts and release limitations are in README-FIX-153.md and FIX153-VALIDATION.md. Real MySQL/JPA, Windows process exclusion/shutdown, crash injection, reconnect/load/soak and same-window Production/Replay acceptance are open. The external Jenkinsfile/deployment scripts were absent from the upload; their old source-contract assertions are replaced with tests of this package's OFF defaults. External deployment integration remains unverified.

Validation also found and corrected a pre-existing FIX-152 stale-token success acknowledgment: completed shared protection now verifies its exact owner before returning success. This has no OFF runtime role and never enables replay.
