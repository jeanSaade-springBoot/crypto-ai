## Exact recovery contract

On the existing five-second monitor, before the separate FIX-150 transaction,
probe the consumer state by symbol PK; only a REVIEW_REQUIRED marker opens the
new bounded recovery transaction. Lock consumer state, then its delivery PK,
then the unique source price record. Recheck durable cutover authority.

Require canonical 1m, phase 1, PROCESSING/PENDING status, completed REJECTED
protection, no protection start or owner, LEGACY_UNKNOWN/NOT_ENTERED apply state,
analysis WAITING with no analysis start/completion, observer PENDING, exactly one
PENDING price record, and no source-event-linked processing work.

Atomically replace the exact old marker token with a fresh token, set ACTIVE and
the current process identity/update time, and insert REJECTED_MARKER_RESUMED audit
with old/new tokens, old/new process, exact evidence and UTC/KSA timestamps.
Audit failure rolls back takeover. Delivery/price/protection evidence is NOT
rewritten by this helper. No manual action is required for this exact state.

The existing phase walk rechecks current ownership under the same symbol lock
before every phase's effects. An already-open old phase transaction finishes or
rolls back before takeover obtains that lock; a delayed old caller loses its
subsequent ownership check after the token changes. Independent protection apply
also checks durable protection completion. This is a lock + evidence + token
fencing protocol, not proof based on elapsed time or process death.

The normal stage-1 completed-protection branch sees REJECTED and sets the pending
price to HISTORICAL_ONLY without onPrice. Stage 2 skips observer application for
that rejected price; normal stage 3 preserves existing candle eligibility and
historical-analysis rules; phase 4 clears the marker. Current candles then proceed.
The helper does not invoke processNext recursively or nest REQUIRES_NEW under locks.
Stop all old trader instances before replacing the binary; mixed protocols are
not accepted as ownership proof.

## Explicit exclusions

phase-2 observer uncertainty, analysis/work uncertainty, conflicting/missing price
rows or unapproved cutover. Existing FIX-150 recovery handles its separate cases.

cannot guarantee all 21 symbols recover or eliminate database contention.
Production recovery timing changes; strategy/exit code and Replay logic are
unchanged. Run matching Production/Replay business regression and stop-crossing
acceptance; unchanged source formulas alone do not establish runtime parity.
