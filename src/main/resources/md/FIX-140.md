## Implemented scope

A shared signal's first wallet-symbol SELECT FOR UPDATE may schedule a retry only when a private marker proves the failure occurred at that call, the exception is a recognized lock timeout/deadlock, and Spring afterCompletion reported ROLLED_BACK. SQLState 08 communications failures do not qualify. Business/commit failures retain review behavior.

The existing shared LIVE dispatcher resumes the exact registered signal. It owns all attempts; SignalProcessingRecovery remains deferred in shared mode. Retry delays are 1/3/10 seconds, with four total attempts; there is no sleep and no held connection during the delay. The existing latest-candle/freshness gate runs after lock acquisition on retries. Expired attempts map to EXECUTION_EXPIRED; exhausted proven non-executions map to EXECUTION_NOT_EXECUTED. No signal regeneration or wallet replay is granted by an Optional.empty result. Persistence uncertainty retains review.

Work state SYMBOL_LOCK_RETRY with failure_stage INITIAL_SYMBOL_LOCK_ROLLED_BACK is new evidence, not a reinterpretation of old QueryTimeoutException strings. Generic REVIEW_REQUIRED records cannot enter this path. A crash between work persistence and delivery persistence remains review-only; automatic incident reconciliation is not implemented.

Initial-position deadlock behavior remains the existing two-attempt policy. Protection failures in ENA/ICP/SUI are not automatically repaired by this patch. Existing incident records require separate evidence-based reconciliation.

## Historical queue handling

No DELETE statement is introduced. Source candles, existing trade_signal rows, wallet records, and consumer checkpoints are retained. An opt-in worker retires only untouched expired phase-4 PENDING/HISTORICAL_DEFERRED analysis rows, with absent analysis start/completion markers and no processing/wallet or incomplete-protection evidence. It records HISTORICAL_SKIPPED, retirement time, reason and operation identity; it does not fabricate analysis_completed_at.

Owner tokens retained from the price phase are not analysis claims. Eligibility is rechecked under symbol-state then delivery-row locks. Active analysis is excluded by status and attempt markers. Keyset scan progress avoids repeatedly encountering ineligible queue heads; it is advisory and resets when exhausted. Each tick scans one symbol/interval lane, at most 20 candidates, with independent three-second mutation transactions. V95 supplies the lane selection index; inspect EXPLAIN on the target MySQL server before enabling writes.

Compatibility defaults:
- shared-market.analysis.historical-enabled=true
- shared-market.analysis.retirement-enabled=false
- shared-market.analysis.retirement-dry-run=true
- shared-market.analysis.retirement-retain-seconds=172800

```
--shared-market.analysis.historical-enabled=false
--shared-market.analysis.retirement-enabled=true
--shared-market.analysis.retirement-dry-run=true
--shared-market.analysis.retirement-retain-seconds=0
```
After reviewing dry-run evidence, changing retirement-dry-run to false enables mutation. Zero extra retention never retires a still-live close. RUNNING, REVIEW_REQUIRED, previously attempted, processing-attributed, or unresolved protection rows are not retired. Retiring every database history record is intentionally not provided.

Disabling historical recovery can remove future reconstruction of missing decision context. This is not proven neutral for live trading. Existing saved context is retained, but keeping stored signals does not prove missing inputs are adequately covered. Consumers include MTF, same-interval BTC, position protection, opportunity consolidation, execution intelligence and validation. Bounded context restoration and Production/Replay context-window acceptance are NOT implemented here. History therefore remains enabled by default.
